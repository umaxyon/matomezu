# 作業の進め方

## 決めてから作る

- 決まっていない操作や見た目は、作る前にユーザーに確かめる。選択肢を出すときは、何に使い、無いと何ができないかを先に書く
- 「理解を合わせたい」「触らない」と前置きされた問いには、説明だけを返して動かさない
- 作っている途中で残した細かな保留は、まとめてユーザーに渡す（勝手に決めない）。refactor-review が「聞かずに進めてよい」とした物は除く
- warning の文は、ユーザーに聞かずに、勧める案で決める
- プラグイン API には、プラグインの作り手に要りそうな物は出す方に倒す。新しく出すときと、出した物の引数を変えるときは、要るならユーザーに聞かずに行う。出さないと決めたときは、理由を添えてユーザーに聞く。出した名前を変える・消すときと、名前が用語集に無い新しい言葉になるときは、今までどおり聞く

## テスト

- 単体のテストは `test/` の下に、確かめる物の置き場で分けて置く。クレートの物は `test/<クレート>/`、プラグインの物は `test/plugins/<プラグインの置き場>/`（`web/src/plugins` と同じ並び。`base`・`items/line` など）、`scripts/` のスクリプトの物は `test/scripts/`。AI ごとの部品（`clients/<AI の名前>/`）の TS の物は `test/clients/<AI の名前>/`。`test/` の直下には全体を見張るテストだけを置き、規約を見張るテストは `test/rules/<規約の md の名前>.test.ts` に置く（テストが見張る）。単体のテストの手伝いのファイルは、使うテストの置き場に置く（いくつもの置き場で使う物は `test/` の直下）
- 作業中は、直したものに関係するテストだけを流す（`bun test test/<置き場>/xxx.test.ts`・`go test ./internal/xxx -run Xxx`・`bunx playwright test e2e/xxx.spec.ts`）
- 全部を流すのは、取り込みのキュー（「コミット」）と、ユーザーに画面の確認を頼む前と、main に直接積むときのコミットの前だけ
  - 単体: `bun test`
  - Go: `go test ./...`（リポジトリの根から動かす）
  - 型: `bun run typecheck`
  - lint: `bun run lint`（取り込みのキューだけ。ほかでは「コミット」のフックに任せる）
  - e2e: `bun run e2e`
- 速さは `bun run e2e:perf` で測る。全部のテストには入れない
- ループバックの外に出る Go のテスト（本物の mDNS のマルチキャストなど）は、`MATOMEZU_TEST_LAN=1` のときだけ流す。全部のテストには入れない。関わる所を直したときは付けて流す
- e2e は、画面をホストに通して確かめる
- e2e のテストは、ほかのテストが残した状態に頼らない。使うブックは、そのテストが用意の口で置く
- e2e は `web/src` の値を読まない（画面とホストの外から確かめる）。型は読んでよい。e2e が読む `test/` のファイルが読む物も含めて、テストが見張る
- e2e は、決まった時間だけ待って先へ進まない（`e2e/perf` は除く）。待つのは画面の様子が変わることにする（時間に頼る所は `e2e/helpers` の `afterFrames` か `page.clock`）。テストが見張る
- `bun test` の結果は末尾だけでなく、pass と fail の行を見る
- テストの用意（データを置く・消す・状態を覗く）のためだけの関数と、常駐の HTTP のパスは、置いてよい。「データを変える入口はアクションだけ」の決まりは、この用意に限って外してよい（クレートの読み込みの向きなど、ほかの決まりは外さない）。確かめたい操作そのものは、アクションと画面を通す
  - 関数は名前の終わりを `ForTest` に、HTTP のパスは `for-test` を含む名前にする
  - TS の物は `test/`・`e2e/` に置き、`web/src` には置かない。Go の物は `_test.go` か、ビルドタグ `e2e` のファイルに置き、本番の実行ファイルに入れない。本番のコードから呼ぶ所が要るときは、ビルドタグ `!e2e` のファイルに同じ名前の中身の無い関数を置き、本番のコードはそれを呼ぶだけにする
  - Go の物を e2e の常駐と Go のテストの両方で使うときは、ビルドタグ `e2e` のファイルと `_test.go` に同じ中身で置く（Go のテストはタグを付けずに流す）
  - テスト（`test/`・`e2e/`・e2e の常駐を作るスクリプト）の外から使っていないこと、ビルドタグ `e2e` で組むのは e2e の常駐だけなこと、上の置き方を、テストが見張る

## ビルドと常駐

- ホストのエンジン（`web/src/engine`）か、それが読む core とプラグインを直したら `bun run build:engine` で `internal/engine/engine.js` を作り直す（テストが見張る）
- 開発は `bun run dev`。Go の常駐を `.dev-home` で立て、`web/dist` を配る。ポートは `bun run dev --port <番号>` で選び、`.dev-home` が覚える。直したら起動し直し、開いているタブも読み直す
- フォントの版を変えたら `bun scripts/fonts.ts widths` で字の幅の表を作り直す（テストが見張る）
- アクションを足したら、常駐の実行ファイルを作り直して起動し直すまで、画面からも AI からも使えない
- 常駐を止めるコマンドと立て直すコマンドは、別々に動かす
- 開発でも `clients/claude-code` を Claude Code のプラグインとして入れ、PATH から `.dev-home/matomezu`（Windows は `.dev-home/matomezu.exe`）を呼べるようにする（リンクを置くなど。プラグインは PATH の matomezu を呼ぶ。入れないか PATH に無いと、AI は参加を受け入れられても準備中のままになる）

## コミット

- main に直接積む。ただし平行作業の worktree では、その worktree のブランチに積み、main のセッション（main_manager）に main への取り込みを頼む。平行作業のブランチを main へ入れるのは、main_manager が動かす取り込みのキュー（`bun scripts/merge-queue.ts <ブランチ>...`）だけで、手で fast-forward やマージをしない。全部のテストと、入れたあとの常駐などの作り直しはキューが行うので、頼む側も main の側も自分ではしない。キューが外したブランチ（衝突・テストの落ち）は、ブランチの側で直して頼み直す。捨てるかもしれない試みだけブランチを切り、戻る目印はタグ（このブランチを main に入れるときは、main に直接積むときと同じに確かめる）
- 平行作業の worktree から取り込みを頼む前は、次の順に確かめる。1 変更を全部コミットする 2 main の最新を取り込む 3 テストを流す（「テスト」の作業中の決まり） 4 conventions-review に見せる。3・4 のあとに直したら、直した分を流し直し、見せ直す
- 区切りのコミットは頼まれなくてよい。push は頼まれたときだけ
- コミットのたびに、フック（`.githooks/pre-commit`）が、ステージした物に format を当ててから lint を流し、誤りがあればコミットを止める。format と lint は自分では流さず、止められたら lint の誤りだけを直す。フックは `git config core.hooksPath .githooks` で入れる（リポジトリに 1 回。全部の worktree に効く）
- サブエージェント conventions-review（`.claude/agents/conventions-review.md`）で、変更が規約に違反していないかを確かめる。違反があれば直す。見せる物は、取り込みを頼む前なら main との差分、main に直接積むときと、main で衝突を解いてマージのコミットを作るときは、コミットの前のステージ済みの変更
- 見せる差分が利用者向けマニュアルの下書き（`.claude/matomezu-manual-memo.md`）だけのときは、conventions-review を省く
- AGENT.md の「利用者向けマニュアル」のとおりサブエージェント manual-creator（`.claude/agents/manual-creator.md`）が書き足した下書きは、書き足しを終えたらコミットする。返ってきた問いには答えるかユーザーに聞き、使い方の不備はユーザーに伝える
- メッセージは英語で、何をどう変えたかを書く。Co-Authored-By を付けない
- `docs/`（`docs/concept.md`・`docs/usecase.md` のほか）・`_old_docs/`・`tmp/` はコミットしない
