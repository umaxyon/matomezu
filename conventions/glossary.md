# 言葉

コード・コメント・規約・会話で使う言葉。ここに無い言い方で、ここにある物を呼ばない。

## matomezu の形

| 言葉 | 意味 |
|---|---|
| matomezu | 製品全体 |
| 土台 | 層の `core`・`store`・`ui`。プラグインを受け取って組み立て・動かす枠と、その枠が決める言葉（ステージ・ページ・置いたアイテムの外枠など）。具体的な機能は持たない。base は含めない |
| core | フォルダ `web/src/core`。土台の層の 1 つ（データの形・定義の型・core 台帳・純粋な関数） |
| base | プラグイン `plugins/base`（`@matomezu/base`）。ビルトインプラグインの 1 つで、ほかのプラグインが読んでよい例外。「土台」と呼ばない |
| インスタンス | `createMatomezu` が生成した `MatomezuInstance` のインスタンス。機能台帳（core 台帳と store 台帳）・組み立てで決まる値（`home`・`autoSkin`）・状態・操作を持つ、動いている matomezu 1 つ分。画面に 1 つ、テストごとに 1 つ |
| ホスト | 常駐サーバーそのもの（Go。`internal/`）。「常駐」はホストと同じ意味 |
| ホストクライアント | 画面の中で、ホストと外の世界に頼む口（`web/src/host-client`。`HostClient`・`serverClient`・`memoryClient`・`openClient`） |
| ホストのエンジン | `web/src/engine`。ホストの goja で、画面と同じアクションを行う入口（`internal/engine/engine.js` にまとめて埋め込む） |

## プラグイン

| 言葉 | 意味 |
|---|---|
| プラグイン | 定義の束。登録の単位。「部品」は別名 |
| ビルトインプラグイン | matomezu に同梱され、`BUILTIN` に並ぶプラグイン（base・master・paper・box・list・line・shape・drawing・flowchart・tree） |
| 追加プラグイン | インストールされたプラグイン。開発中に開発者プロジェクトを結んだ物も、完成品も同じ。作り手の属性は持たない。プラグイン API と、ほかのプラグインの連携ポイント（型だけ）を読む |
| 開発者プロジェクト | 追加プラグインを作るプロジェクト。matomezu の中（このリポジトリ）は含まない。利用者のローカルの Claude が作るときの作業の場所も同じ |
| プラグイン API | 追加プラグインとビルトインプラグインが使ってよい名前と型の約束。`web/src/plugin-api` に集め、実装は動いている matomezu が渡す。入口は `matomezu`・`matomezu/ui`（`web/src/plugin-entry`）と `matomezu/catalog`（`core/catalog.ts`） |
| `plugin-modules` | 追加プラグインが借りる、名前から実物を引く表（`web/src/plugin-modules`）。キーは import の名前（`matomezu`・`matomezu/ui`・`react` など）、値は動いている matomezu が持つ実物。ホストのエンジンと画面が、追加プラグインを動かす前に渡す |
| `matomezu/testing` | 開発者プロジェクトのテストで、ビルトインプラグインと自分のプラグインで matomezu を丸ごと組む入口（`web/src/testing`）。テストのプロセスの中で組み、ホストは使わない。プラグイン API に含めない |

## 機能台帳

| 言葉 | 意味 |
|---|---|
| 機能台帳（catalog） | 部品が足せる定義の種類ごとに、足された定義を並べた全体。利用者に価値を届ける最小の単位の全部 |
| core 台帳 | `CoreCatalog`（`core/core-catalog.ts`）。画面とホストが共に使う定義（ブックのタイプ・アイテム・アクション・設定の項目・見せ方・道具・道具の組・テーマ・紙・スキン・文言の組・言語パック・プラグインが持つテーマキー） |
| store 台帳 | `StoreCatalog`。画面だけが使う、React の無い定義（コマンド・ダイアログ・キーの既定の割り当て） |
| ui 台帳 | `UiCatalog`。画面だけが使う、React の定義（ビュー・ウィジェット・コマンドのアイコン・道具のアイコン・差し替え）。実体は `MatomezuProvider` が持つ |
| MCP 公開ツール | AI が MCP で呼べる処理（`actions`・`perform`・`view`・`list_books`・`read_book`・`read_settings`・`show`）。いつも「MCP 公開ツール」と呼び、「道具」とは呼ばない |
| error | その状態では matomezu が進めない間違い。組み立てでも実行中でも、投げて止める（組み立てなら、ビルトインプラグインはインスタンスを作らず、追加プラグインはそのプラグインを外す。実行中なら、その操作を止める）。番号は E と 3 桁で、一覧は `core/errors.ts` |
| warning | 止めるほどではない間違い。止めずに、その物（定義の 1 行・ブック 1 冊・画面が組めずに外した追加プラグインなど）だけを効かなくし、一覧に残す（常駐のログ・画面・AI）。番号は W と 3 桁で、一覧は `core/warnings.ts` |

## 定義とデータ

| 言葉 | 意味 |
|---|---|
| 定義オブジェクト | プラグインが機能台帳に足す、定義 1 つを表すオブジェクト。型の名前は `〇〇Def`（`ItemDef`・`ToolDef`・`ToolSetDef` など。definitions の「定義の表」）。フィールドとメソッドを持つ。プラグインを読み込んだときにでき（`define…`。文言の組は `pluginKit` が作る）、機能台帳はそれを id ごとに 1 つ並べる。ほかの定義オブジェクトのフィールドとして書く物（アイテム・ブックのタイプが持つテーマキー）は、機能台帳には並ばず、その定義オブジェクトの中にある。組み直す（追加プラグインを足す・外すなど）まで同じ物を使う。同じ種類のアイテムをいくつ置いても、定義オブジェクトは 1 つ。説明では「定義オブジェクトとして `〇〇Def` を足す」と言う |
| データオブジェクト | ブックの中身として保存し、ホスト・画面・AI がやり取りするオブジェクト（ブック・ページ・置いたアイテムなど）。JSON にして保存するので、フィールドだけを持ち、メソッドは持たない |
| フィールド | オブジェクト（定義オブジェクト・データオブジェクト・`matomezu.json` など）が持つ、名前の付いた値 1 つ（`pans: true`・`title` など） |
| メソッド | 定義オブジェクトのフィールドのうち、値が関数のもの（アイテムの `tidy`・`minimap` など）。読む側（土台か、拡張ポイントに書き足したプラグイン）が、その定義について聞くために呼ぶ |
| 定義オブジェクトの拡張ポイント | 定義オブジェクトの型が種類ごとに含む、空の型（`core/catalog.ts` の `ShapeItemExtras` など）。ほかのプラグインの定義オブジェクトに答えてもらうフィールド・メソッドを、読む側のプラグインが `declare module` で書き足す。短く「拡張ポイント」とも呼ぶ |
| 連携ポイント | プラグインの提供者が、ほかのプラグインに答えてもらうために、拡張ポイントへの書き足しを型だけで出すパッケージ。答えるプラグインは、それを `import type` で読む。処理も値も持たない |

## ブックの中身

| 言葉 | 意味 |
|---|---|
| アイテム | ページに置く物（箱・ひし形・リスト・線など）。データに残る。置いた 1 つ 1 つも、その種類（定義 `ItemDef`）もアイテムと呼ぶ。位置と大きさを持つ形（`kind: "shape"`）と、2 つの形をつなぐもの（`kind: "connector"`。線など）がある。形の中に持つ中身（リストの行など）と、並べ方から描くだけでデータに無い物（ツリーの線など）はアイテムではない |

## 画面

| 言葉 | 意味 |
|---|---|
| コンポーネント | 画面の React のコンポーネント。部品（プラグイン）とは別の物 |
| ビュー | コンポーネントのうち、定義に結んで描く物（`XView`・`presentationViews`・`dialogViews`・`settingViews` など） |
| スロット | ウィジェットを差し込む場所の id。ウィジェットの中にも作れ、描くプラグインが自分の名前で足す（例: `@matomezu/base:stage-top`）。いちばん外の 1 つだけが `root` |
| テーマキー | アイテム・ブックのタイプ・プラグインが宣言する、テーマの値の名前（`@matomezu/box:box-fill` など）。どんなテーマキーがあるかはテーマごとに変わらず、値がテーマごとに決まる。コードでは `tokens`・`TokenDef`。「フィールド」とだけ呼ばない |
| スキンキー | 土台が決める、スキンの値の名前（`bg` など）。どのスキンも全部の値を持ち、CSS 変数 `--skin-<スキンキー>` になる。コードでは `SkinToken`。「フィールド」とだけ呼ばない |
| キーの範囲 | キーの割り当てが効く場面の名前（`KeyScopeTable`）。土台の `stage`・`dialog`・`menu`・`global` と、プラグインが足す範囲（`<プラグインの id>:<名前>`）。`global` は、ダイアログもメニューも開いていないとき、`stage` の次に探す |
| 窓 | matomezu の画面を開いているタブ 1 つ（いま前に出ているタブとは限らない）。ホストは、つながっている窓ごとに、見ているものとフォーカスの順を覚える |
| タブ | ブラウザのタブ（一般の言葉。窓だけを指すのではない）。「タブ」とだけ言えばこちら |
| ページタブ | matomezu の画面の中の、ブックのページを切り替えるタブ |
| 入力Form | 画面で値を入れる物 1 つ（テキスト・チェックボックス・セレクトなど）。種類を言うときはテキストForm・チェックボックスForm・セレクトForm |
| 道具 | ステージでポインタが何をするか（選択・ハンドなど。`ToolDef`） |
| 道具の組 | ステージで切り替える道具の並び（`ToolSetDef`）。ブックのタイプが id で名指す |

## 使わない言葉

アプリ・ユーザーアプリ・ユーザープラグイン・SDK・実行エンジン・核・コア・中の部品・外のプラグイン・型の表・登録表・目録・画面パーツ・画面コンポーネント・ビルトイン部品・欄（オブジェクトの値はフィールド、画面で値を入れる物は入力Form）
