# 言葉

コード・コメント・規約・会話で使う言葉。ここに無い言い方で、ここにある物を呼ばない。画面の文言はこの表で縛らない。
ここには言葉の意味と呼び方の決まりだけを書き、作り方の決まりは本文の 1 か所に書く。

## matomezu の形

| 言葉 | 意味 |
|---|---|
| matomezu | 製品全体 |
| クレート | architecture の「クレート」の表に並ぶ、`web/src` の下のフォルダ 1 つ（`core`・`store`・`plugins` など）。読んでよい物はクレートごとに決まる。`core` クレートのように呼ぶ。Go の `internal/` の下はパッケージと呼ぶ |
| 土台 | `core`・`store`・`ui` の 3 つのクレート。プラグインを受け取って動かす枠。base は含めない |
| core | `web/src/core` のクレート。土台のクレートの 1 つ（データの形・定義の型・core 台帳・純粋な関数） |
| base | プラグイン `plugins/base`（`@matomezu/base`）。ビルトインプラグインの 1 つで、ほかのプラグインが読んでよい例外。「土台」と呼ばない |
| インスタンス | `createMatomezu` が生成した `MatomezuInstance` のインスタンス。機能台帳・台帳アセンブルで決まる値（`controlCenter`・`autoSkin`）・状態・操作を持つ、動いている matomezu 1 つ分 |
| ホスト | 常駐サーバーそのもの（Go。`internal/`）。「常駐」はホストと同じ意味 |
| matomezu 保管庫フォルダ | 利用者ごとに 1 つの、ホストが使うフォルダ（`internal/home`） |
| ホストクライアント | 画面の中で、ホストとブラウザ（URL・履歴・クリップボード・印刷など）に頼む口（`web/src/host-client`。`HostClient`） |
| ホストのエンジン | ホストの goja で、画面と同じアクションを行う入口（`web/src/engine`） |

## プラグイン

| 言葉 | 意味 |
|---|---|
| プラグイン | 定義の束。登録の単位 |
| ビルトインプラグイン | matomezu に同梱され、`BUILTIN` に並ぶプラグイン |
| 追加プラグイン | インストールされたプラグイン。開発中に開発者プロジェクトを結んだ物も、完成品も同じ。作り手の属性は持たない。プラグイン API と、ほかのプラグインの連携ポイント（型だけ）を読む |
| 開発者プロジェクト | 追加プラグインを作るプロジェクト。matomezu の中（このリポジトリ）は含まない。利用者のローカルの Claude が作るときの作業の場所も同じ |
| プラグイン API | 追加プラグインとビルトインプラグインが使ってよい名前と型の約束。入口は `matomezu`・`matomezu/ui`・`matomezu/catalog` |
| `plugin-modules` | 追加プラグインが借りる、import の名前から実物を引く表（`web/src/plugin-modules`） |
| `matomezu/testing` | 開発者プロジェクトのテストで、ビルトインプラグインと自分のプラグインで matomezu を丸ごと組む入口（`web/src/testing`） |

## 機能台帳

| 言葉 | 意味 |
|---|---|
| 機能台帳（catalog） | プラグインが足せる定義の種類ごとに、足された定義を並べた全体（core 台帳と store 台帳）。ui 台帳は含めない。利用者に価値を届ける最小の単位の全部 |
| 台帳アセンブル | プラグインの定義を集めて core・store・ui の台帳を作り、食い違いを確かめること。コードでは `assemble`・`assembleUi` |
| core 台帳 | `CoreCatalog`（`core/core-catalog.ts`）。画面とホストが共に使う定義の台帳 |
| ノーマライズステップ | ブックが対象のアクションの run のあとに、perform がどのブックにもかける処理（可変ページの中身のずらしなど）。コードでは `NormalizeStepDef` |
| store 台帳 | `StoreCatalog`。画面だけが使う、React の無い定義の台帳 |
| ui 台帳 | `UiCatalog`。画面だけが使う、React の定義（ビューなど）の台帳 |
| MCP 公開ツール | AI が MCP で呼べる処理（`actions`・`perform` など）。いつも「MCP 公開ツール」と呼び、「道具」とは呼ばない |
| 目次 | 全文の代わりに、id と見分けに要る物だけを並べた物。中身は id を渡して取る。例: ブックのページの目次・ページのアイテムの目次・`actions` の目次。コードでは `index`・`outline` |
| error | その状態では matomezu が進めない間違い。投げて止める |
| warning | 止めるほどではない間違い。止めずに、その物（定義の 1 行・ブック 1 冊など）だけを効かなくする |

## 定義とデータ

| 言葉 | 意味 |
|---|---|
| 機能定義 | 具体的な機能を足す定義（アイテム・アクションなど） |
| 構造定義 | ほかの定義が共通に使う言葉の定義（文言の組など） |
| 定義オブジェクト | プラグインが機能台帳に足す、定義 1 つを表すオブジェクト。型の名前は `〇〇Def`（`ItemDef`・`ToolDef` など。definitions の「定義の表」）。フィールドとメソッドを持つ。id を持たずにプラグインに書く物（ノーマライズステップなど。関数 1 つの物もある）も `〇〇Def` と名付ける。画面の側で定義に付ける見た目（`ItemUi` など）には付けない。同じ種類のアイテムをいくつ置いても、定義オブジェクトは 1 つ。説明では「定義オブジェクトとして `〇〇Def` を足す」と言う |
| 利用者の設定 | 利用者ごとの設定（言語・スキンなど）。ブックのデータではなく、利用者の設定の項目の id → 値で持つ。ブック・ページの設定（ブックの設定）とは分けて呼ぶ |
| role | 土台が読む利用者の設定の項目に付ける印。土台は項目を id でなく role で引く。訳さず role と呼ぶ。常駐が読む対象の定義（参加者・ワークルーム）にも付け、常駐は種類を id でなく role で引く |
| データオブジェクト | ブックの中身として保存し、ホスト・画面・AI がやり取りするオブジェクト（ブック・ページ・置いたアイテムなど）。JSON にして保存するので、フィールドだけを持ち、メソッドは持たない |
| フィールド | オブジェクト（定義オブジェクト・データオブジェクト・`matomezu.json` など）が持つ、名前の付いた値 1 つ（`pans: true`・`title` など） |
| メソッド | 定義オブジェクトのフィールドのうち、値が関数のもの（アイテムの `tidy`・`minimap` など）。読む側（土台か、拡張ポイントに書き足したプラグイン）が、その定義について聞くために呼ぶ |
| 定義オブジェクトの拡張ポイント | 定義オブジェクトの型が種類ごとに含む、空の型（`core/catalog.ts` の `ShapeItemExtras` など）。ほかのプラグインの定義オブジェクトに答えてもらうフィールド・メソッドを書き足す所。短く「拡張ポイント」とも呼ぶ |
| アノテーション | ブックの物（id を持つ物）に、その id で結び付き、ブックのデータとは別に残る物。種類はプラグインが定義（`AnnotationDef`）で足す |
| AI の応えを待つ物 | アノテーションのうち、AI が読むか応えるのを待っている物 |
| 伝言 | base のアノテーションの種類。利用者が物に付けて AI に伝える文（コードでは `note`） |
| マーク | base のアノテーションの種類。物を指すだけの、文の無い印。伝言とは別。つなぐものが形に求める見た目（`ShapeMarksProvider`）とも、ミニマップの絵（`MinimapMark`）とも別 |
| 連携ポイント | プラグインの提供者が、ほかのプラグインに答えてもらうために、拡張ポイントへの書き足しを型だけで出すパッケージ。処理も値も持たない |

## ブックの中身

| 言葉 | 意味 |
|---|---|
| アイテム | ページに置く物（箱・ひし形・リスト・線など）。データに残る。置いた 1 つ 1 つも、その種類（定義 `ItemDef`）もアイテムと呼ぶ。位置と大きさを持つ形（`kind: "shape"`）と、2 つの形をつなぐもの（`kind: "connector"`。線など）がある。形の中に持つ中身（リストの行など）と、並べ方から描くだけでデータに無い物（ツリーの線など）はアイテムではない |
| スライド | スライドのブックのタイプのページ 1 枚。コードでは `slide`。ページの `slide` の並び（形だけの物。Frame ではない）は、スライドのブックでは本体、ほかのブックでは背景と呼ぶ |
| 背景 | 背景を持つタイプのページの `slide` の並び。ブックの中身（`items`）の下に敷く、直す物 |
| 背景編集モード | ステージが、ページの背景を直している間。ステージの状態の 1 つ |
| 描画シェイプ | `@matomezu/slide` のアイテム。ページの `slide` に置く。シェイプとは別の物で、シェイプとだけ言わない（シェイプの行を見る） |
| ドラッグ枠 | 何も無い所からドラッグしている間に出る、選ぶ範囲の四角（コードでは `dragFrame`）。選ぶだけで置かない。Frame（アイテムを置ける領域）でも、ゴースト（置く前の点線の枠）でもない |
| Frame | アイテムを置ける領域。ページの紙（可変ページでは、印刷区画を並べた広さ）と、子を持てる形の子の領域。中では紙に収める決まりで並べる |
| 可変ページ | 中身が広がった分だけ、紙の大きさの印刷区画を増やすページ。増やす向きは、上・下・左・右のどれへ増やすか。データではページの `grows` |
| 印刷区画 | 印刷と印刷プレビューで、紙 1 枚に当たる 1 つ。可変ページでは、ページを紙の大きさで区切った 1 つ（データに無く、ページの中身の広がりから決まる）。可変ページでないページは、1 ページが 1 つの印刷区画。印刷区画の話の中では「何区画目」と数えてよい。印刷区画を「区画」とだけ言わず、「何ページ目」とも数えない（ページと紛れるため）。コードでは sheet |
| フラグメント | マークダウンの文書の中で、リンクの `#` の後ろに書く、文書の中の飛ぶ先の名前（見出しなどに付く）。データに無く、本文から決まる。コードでは `fragment`。飛ぶ先をアンカーと呼ばない（アンカーはスタンドの付け先）。React の `Fragment` とは別で、ほかの意味（断片など）では使わない |
| 子の領域 | 子を持てる形の中で、子を置く所。Frame の 1 つ |
| ロック | ブックやページ、ロックできる種類のレコードに掛ける「変えない」の印。編集ロックとは別の物 |
| 認可ステップ | アクションを、ブックのある所やレコードに対して行ってよいかを決めるステップのうち、止めるだけの物（`PermissionDef`。ロックなど）。いつも「認可ステップ」と呼ぶ |
| 許可スコープ | アクションやコマンドが、何（ブックの所・一覧のブック・利用者の設定の項目）を変えるかの宣言。認可ステップがこれで止めるかを答える。コードでは `permissionScope` |
| ケイパビリティ | アイテムの定義が宣言する名前の並び。どれを持つかで、土台と足したプラグインが振る舞いを変える。コードでは `capabilities` |
| ゴミ箱 | 一覧から外したブックを置く所。戻せる。ゴミ箱から消すと戻せない |
| シェイプ | 形のうち、決まった大きさの絵と、その下に書く文字を持つもの（スティックマン・DB など）。子を持てない。中に文字を書く形（角丸・ひし形など）はシェイプではない。コードの `shape`・`Shape…` は形を指し、シェイプだけを指さない。`@matomezu/slide` のアイテムは描画シェイプと呼び、シェイプではない |

## 画面

| 言葉 | 意味 |
|---|---|
| コンポーネント | 画面の React のコンポーネント |
| ステージ | ブックを 1 つ開いて見せる、画面の見える領域の 1 つ。コードでは `Stage`。git のステージとは別 |
| ウィジェット | 画面の物 1 つ（ui 台帳の `WidgetDef`）。スロットに置くか、開く側が渡して出す |
| UI マッピング | ウィジェットマッピングとコマンドマッピングの組。コードでは `LayoutDef` |
| ウィジェットマッピング | UI マッピングのうち、ウィジェットをスロットに置く所（`slots`） |
| コマンドマッピング | UI マッピングのうち、コマンドをメニュー・右クリックのメニューに並べる所（`menus`・`contextMenus`・`anchorMenu`） |
| ミニマップ | ページの縮小した見取り図（base）。サムネイルとは別 |
| matomezu 外観枠 | 画面のうち、ブックの中身でない所全部。色や形はスキン（利用者の設定で選ぶ）が決める |
| ビュー | コンポーネントのうち、定義に結んで描く物（`XView`・`presentationViews`・`dialogViews`・`settingViews` など） |
| ペイン | 見せ方のビューの中を分けた、1 つの見る所（マークダウンの原文とプレビューなど）。コードでは `Pane` |
| レイヤー | スロット `@matomezu/base:book-layers`（ステージの中）か `@matomezu/base:sheet-layers`（印刷区画 1 つの中。印刷プレビュー・印刷・ページ一覧のサムネイル）に置いたウィジェット 1 つ。並べた順に下から重ねる。ビューの中で手前・奥に描く物はレイヤーと呼ばない |
| ラインビュー | 線のつなぐもののビュー（`ConnectorUi` の `view`）。形の並びを包み、形より手前に線を描く。一般に言うときは「つなぐもののビュー」 |
| ゴースト | ポインタに付いてくる、データでない仮の見た目（ドラッグの写し・置く前の点線の枠）。右の長押しで出る道具のアイコンは含めない |
| ゴーストエリア | 画面のいちばん手前の、ゴーストなどドラッグの間だけ出す物を描く所 |
| アンカー | スタンドの付け先。ビューが、id を持つ物（アイテム・リストの行・節・ディレクトリの行など）を描く要素に付ける。中身はその物の id だけで、見た目を持たない。アノテーションは結び付く物の id を持ち、画面ではその id のアンカーにスタンドとして出す（データのフィールド `anchors` は id の並びで、アンカーとは呼ばない） |
| スタンド | アンカーのそばに立つ、データでない見た目（節の色を選ぶ物など）。スタンドのレイヤーに描き、倍率で大きさを変えない。パン・倍率・スクロールで物が動けば付いて動く。ゴーストはポインタに付き、スタンドはアンカーに付く |
| 鳥の配色 | マスコットの鳥の、外羽・内羽・旗の 3 色の組。鳥ごとの元の配色と、名前の付いた組があり、どの鳥にも塗れる。鳥のマークそのものとも、スキンやテーマの配色とも別。コードでは `BirdColors`・`BirdPalette` |
| マークポインタ | マークや伝言（アノテーション）を付けた物が、画面とその物を囲む Revealable（リストの行の並びなど）の重なりの外にある間、そのスタンドが代わりに縁に出す見た目。マークそのもの（アノテーションの種類）とは別。コードでは pointer。「ポインタ」とだけ言えば、マウスなどのポインタを指す |
| コーナーステータス | 物の右上の角に出す、その物の今の様子の印（びっくりマーク・たたんだ伝言・既読の伝言など）。種類ごとにプラグインが名乗り、物ごとに 1 つの角のスタンドにまとめて出す。コードでは corner status。スタンドそのものとも、アノテーション（データ）とも別 |
| Revealable | 中の物の見え方を自分で変えるビューが実装する、外から id の物を見えるようにと頼まれるインターフェース |
| スロット | ウィジェットを差し込む場所の id。ウィジェットの中にも作れ、描くプラグインが自分の名前で足す（例: `@matomezu/base:stage-top`）。いちばん外の 1 つだけが `root` |
| 文字の色 | 本文の一部に付ける、意味の役割の色（`TextColorDef`。成功・情報・注意・エラーなど） |
| 代表色 | どのテーマも持つ、役割ごとの色。物の色に選ぶと、テーマが変わってもそのテーマの色で描く。テーマキーでは `palette.<役割>`。コードでは `palette`。鳥の配色とは別 |
| 本文の装飾 | 本文の文字列の中に書く、太字と文字の色の印 |
| テーマキー | アイテム・ブックのタイプ・プラグインが宣言する、テーマの値の名前（`@matomezu/box:box-fill` など）。どんなテーマキーがあるかはテーマごとに変わらず、値がテーマごとに決まる。コードでは `tokens`・`TokenDef`。「フィールド」とだけ呼ばない |
| テーマタイプ | テーマがどのブックのタイプ向けか。テーマタイプが重なるテーマを、そのタイプのブックと中の形で使える。どのタイプにも向くテーマは `"all"`。base のテーマタイプ `diagram`（図）・`document`（文書）の「図」は、ブックを「図」と呼ぶのとは別。ブックのタイプとも別の物。コードでは `ThemeType`（テーマとブックのタイプの `themeTypes`） |
| スキンキー | 土台が決める、スキンの値の名前（`stage`・`surface` など）。どのスキンも全部の値を持つ。コードでは `SkinToken`。「フィールド」とだけ呼ばない |
| キーバインド | キーとコマンドの組。プラグインの既定（`KeyDef`）と、利用者の設定での変更から決まる（画面ではショートカットキー） |
| キーの範囲 | キーバインドが効く場面の名前と、画面に出す題名（プラグインの範囲は `KeyScopeDef`）。土台の範囲と、プラグインが足す範囲がある |
| その場の編集 | ステージで選んでいる物を、ダイアログを開かずにその場で書き換えている間（編集の道具を選んでいることとは別）。何を編集しているかは選択で決まる |
| 編集ロック | 利用者がある窓で物（id を持つ物。開いた伝言など）を直している間だけ、その物を変える・消す AI のアクションを断る印（`useEditLock`）。データに残らない。ブックの「ロック」とも、その場の編集とも別の物。「ロック」とだけ言わない |
| ページ内検索 | 開いているページの文字の中を探すこと。ブックを開くダイアログで名前からブックを絞る検索とは別 |
| ブック内検索 | ブックの全部のページの文字の中を探すこと |
| 当たり | 検索で見つかった、ページの文字の中の 1 か所。コードでは `SearchHit` |
| 今の当たり | 当たりのうち、次・前で移ってきた 1 つ。1 つ置換の相手 |
| 検索ダイアログ | ページ内検索・ブック内検索と置換をまとめたダイアログ。`DialogDef` のダイアログではない（根のスロットのウィジェット） |
| 置換 | 当たりを置き換える字で替えること。1 つ置換（今の当たり）と全部置換（範囲の当たりの全部）を言い分ける |
| コントロールセンター | ブックでない、利用者に 1 つの入口。窓が前に出す物の 1 つ（`ControlCenterDef`） |
| ブックスクリーン | ステージを並べて、ブックを見る・直す画面。窓が前に出す物の 1 つ。コードでは `Workspace` |
| 前に出している物 | 窓がいま見せている、コントロールセンターかブックスクリーン。コードでは `front` |
| 画面 cookie | 常駐が、「画面から」の入口を開けてよいブラウザと見分ける cookie。AI の入口とは別 |
| 参加者 | AI のセッションがワークルームに入るための記録 1 つ（要求中 `requested` か受け入れ済み `joined`）。受け入れ済みのうち、まだ参加者として数えない物を準備中と呼ぶ |
| AI のフック | AI の側の仕組みで、利用者が話しかけたときなどに matomezu のコマンドを呼ぶもの（Claude Code の `UserPromptSubmit` など）。React のフックとは別 |
| 対象の定義 | プラグインが足す、アクションの対象の種類。コードでは `SubjectDef` |
| レコード | 対象の定義が足した種類のデータ 1 件 |
| アクター | アクションを行った者。利用者か AI（AI は入っているワークルームを持つ。参加が確定していなければ `none`）。コードでは `Actor`。画面の履歴の段の `by`（変更の出どころ）とは別 |
| ワークルーム | 名前・鳥・配色を持つ、独立したデータ。参加者が入る場所 |
| 参加者リスト | ワークルーム・参加者・管理者の印のまとまり（画面の一覧もこう呼ぶ） |
| 空室 | 入っている参加者がいないワークルーム |
| 管理者の印 | 全体に 1 つの、管理者のワークルームを指す印（どこからも読まない飾り） |
| タスクボード | 作業を、レーンに並べたチケットで見せる、`@matomezu/taskboard` プラグインの物 |
| プロジェクト | タスクボード 1 枚。名前・チケットプレフィクス・レーン・チケットタグを持つレコード。開発者プロジェクトとは別 |
| チケット | プロジェクトの 1 枚。名前・本文・レーン・チケットタグ・優先度を持つレコード。「チケット」とだけ言えばこちら（AI 編集チケットは別） |
| レーン | プロジェクトが持つ、チケットを分ける列。AI への指示（プロンプト）を持つ。どのレーンにも入らない物は未分類（表示を切り替えられる） |
| チケットタグ | プロジェクトが持つ、チケットの種類（タスク・バグなど）。使うか（`enabled`）とプロンプトを持つ。コードでは `tag` |
| チケットプレフィクス | チケットの番号の頭（`T-` など）。英字で始まり、英字とハイフンだけ。プロジェクトをまたいで重ならない（大文字小文字を分けない） |
| 参加の有効時間 | 最後に呼ばれてから「生きている」とする長さ。利用者の設定 |
| 画面の場所 | 読み直しても戻す、前に出している物（コントロールセンターかブックスクリーン）、ステージごとに開いているブックとページ・倍率・ずらす量、分割、場所に入れる画面の状態（`PlacedStateDef` の id → 値。ステージごとの物と、ステージに結ばない物）の組。コードでは `Address` |
| 画面の履歴 | 利用者がその窓で行った変更と、その窓で見えた AI とほかの窓の変更の、ブックの変更の並び。ブックごとに持ち、元に戻す（Undo）・やり直す（Redo）で行き来する。ブラウザの履歴（URL）とは別 |
| 画面の履歴の段 | 画面の履歴の 1 単位。利用者の 1 回の操作（コマンド 1 つ・ダイアログの確定・ドラッグの離しなど）か、AI やほかの窓の 1 回のアクションで変わったブック 1 冊の、前と後の組。誰の変更か（`by`）を持つ。コードでは `HistoryStep`。「段」とだけ言わない（作業の段階や認可ステップと紛れるため） |
| まだ見ていない変更 | 画面の履歴に入る AI とほかの窓の変更のうち、その窓でまだ見えていない物。見えたら画面の履歴に入る。郵便の既読（見た郵便）とは別 |
| AI 編集チケット | 常駐が AI の変更ごと（変えたブック 1 冊につき 1 つ）に開く、利用者に見えたかと結果を AI に渡すための記録。アクションも作れる。「チケット」はタスクボードの物を指すので、「AI 編集チケット」と必ず言う。コードでは `AIEditTicket` |
| 窓 | matomezu の画面を開いているタブ 1 つ（いま前に出ているタブとは限らない） |
| タブ | ブラウザのタブ（一般の言葉。窓だけを指すのではない）。「タブ」とだけ言えばこちら |
| ページタブ | matomezu の画面の中の、ブックのページを切り替えるタブ |
| ページ一覧 | ステージの本体の左に、ブックのページのサムネイルを縦に並べる列 |
| サムネイル | ページ 1 枚の縮小した絵（ページ一覧に並ぶ）。「プレビュー」は印刷プレビューと紛れるので、単独で縮小絵の意味には使わない |
| 入力Form | 画面で値を入れる物 1 つ（テキスト・チェックボックス・セレクトなど）。種類を言うときはテキストForm・チェックボックスForm・セレクトForm |
| 道具 | ステージでポインタが何をするか（選択・ハンドなど。`ToolDef`） |
| 道具の組 | ステージで切り替える道具の並び（`ToolSetDef`）。ブックのタイプが id で名指す |
| シェイプパネル | ツールボックスの「形」のボタンで開く、アイテムのアイコンの格子。シェイプのほか、中に文字を書く形も並ぶ。並べるかはアイテムの定義が書く。描画シェイプは並べない（描画シェイプの行を見る） |
| 右サイドパネル | 窓の右端に出す base の入れ物。窓に 1 つで、中身はスロットに置いたウィジェットのうち、開いている 1 つ |
| 印刷プレビュー | ステージの見え方の 1 つ。開いたブックの全ページの印刷区画を、刷るとおりに並べて見せる（見るだけ）。印刷プレビューを「プレビュー」とだけ言わない（マークダウンのペインのプレビューと紛れるため）。コードでは `print-preview` |
| フッタメニュー | ステージの下の行から上がる、base のスロットを並べる行 |
| 左サイドパネル | 窓の左端に出す base の入れ物。ステージでなく窓に属する。窓に 1 つで、中身は開く側が渡した左サイドパネルのタブの組のうち、左サイドパネルのタブで選んだ 1 つ |
| 左サイドパネルのタブ | 左サイドパネルの上に並ぶ、中身を切り替えるタブ。ブラウザのタブとは別 |
| 左サイドパネルのタブの組 | 開く側が左サイドパネルに渡す、左サイドパネルのタブのウィジェットと、その view に渡す物の並び。コードでは `entries` |
| 送信トレイ | 左サイドパネルのタブの 1 つ。開く側が渡したステージで開いているブックのアノテーション（伝言・マークなど）を、ページごとに付けた時点の新しい順に並べる |
| 設定画面 | 利用者の設定とキーバインドを変える画面。ブックやページの設定のダイアログとは別の物 |
| 設定カテゴリ | 設定画面の左の一覧の 1 つ（base の「全体」など）。スロット `@matomezu/base:settings-categories` に置いたウィジェット 1 つ。「設定画面の項目」と呼ばない（設定の項目と紛れるため）。コードでは settingsCategory |
| トースト | 少しの間だけ出て消える知らせ。カード（`card`）とマーキー（`marquee`）の 2 つの見せ方がある |
| マーキー | トーストの見せ方の 1 つ（`form: "marquee"`）。文を横に流して消える |
| 郵便 | 送り手（AI など）が利用者に宛てて送る物。郵便箱に入る。種類はプラグインが定義（`MailDef`）で足す。コードでは mail |
| 変更提案郵便 | AI がアクションを乗せて利用者に届け、利用者が押すと反映される郵便。base の郵便の種類で、コードでは proposal |
| 郵便箱 | 郵便の並び。画面では左サイドパネルのタブの 1 つで見る。コードでは mailbox |
| しおり | まだ見ていない郵便を示す、画面の上から下がる見た目。コードでは bookmark |
| 行き先 | 郵便が示すブック・ページ・ページの中の id を持つ物。コードでは to |
| 送り手 | 郵便を送った者の名前。コードでは from |
| 伝言期限 | 読まれた伝言が、利用者が AI に話しかけてから消えるまでの時間。利用者の設定（コードでは `note-expiry`） |
