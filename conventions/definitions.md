# 定義と機能台帳

機能は、定義（Def）を機能台帳に足すことで増やす。定義は、プラグインと土台がそれぞれ持ち込む。定義には 2 種類ある。

- 機能定義: 具体的な機能を足す定義（アイテム・アクションなど）。プラグインだけが持ち込む
- 構造定義: ほかの定義が共通に使う言葉の定義（文言の組・言語パック・テーマキー・キーの範囲）。プラグインも土台も持ち込む

土台が持ち込むのは構造定義だけ。

## 定義の表

| 表 | 何か | 置き場所 |
|---|---|---|

| コントロールセンター（`ControlCenterDef`） | ブックでない、利用者に 1 つの入口。ブックの一覧・利用者の設定・対象の定義の種類（郵便箱の郵便も）を変えるアクションを許すかと、変えさせない利用者の設定の項目を決める | `core/def/control-center.ts` |

| アクション（`ActionDef`） | 動詞。データを変える物 | `core/def/action.ts` |
| テーマ（`ThemeDef`） | ページの見た目 | `core/def/theme.ts` |
| スキン（`SkinDef`） | matomezu 外観枠の色や形（利用者の設定で選ぶ）。外観枠の代表色は、スキンの明暗ごとの既定があり、`palette` で上書きできる | `core/def/skin.ts` |
| 紙（`PaperDef`） | ページに置く紙の大きさ | `core/def/paper.ts` |
| 文字の色（`TextColorDef`） | 本文の一部に付ける、意味の役割の色（成功・注意など）。色を持つ | `core/def/text-color.ts` |
| 設定の項目（`SettingDef`） | ブックやページ、または利用者の設定に持たせる 1 つの値（線の既定の通り方・言語など） | `core/def/setting.ts` |
| プレゼンテーション（`PresentationDef`） | ページをステージにどう見せ、どう触るか（紙など） | `core/def/presentation.ts` |
| 道具（`ToolDef`） | ステージでポインタが何をするか（選択・ハンドなど） | `core/def/tool.ts` |
| 道具の組（`ToolSetDef`） | ステージで切り替える道具の並び | `core/def/tool.ts` |

| アノテーション（`AnnotationDef`） | ブックの物に id で結び付き、ブックのデータとは別に残る物の種類（伝言など） | `core/def/annotation.ts` |
| 郵便（`MailDef`） | 送り手が利用者に宛てて送る物の種類（手紙など） | `core/def/mail.ts` |

| 対象の定義（`SubjectDef`） | アクションの対象の種類（レコードの種類）。レコード 1 件の形（Zod）と形のほかの確かめ、索引キー、番号を振るか | `core/def/subject.ts` |
| コマンド（`CommandDef`） | 画面の入口（ボタン・メニュー・キーから呼ぶ）。ステージで呼ぶコマンドと、スクリーンから呼ぶコマンドの 2 種類 | `store/commands/def.ts` |
| ダイアログ（`DialogDef`） | 開くダイアログの id | `store/dialogs.ts` |
| 文言の組（`MessageSetDef`） | プラグイン 1 つの、画面に出す文と訳 | `core/i18n/messages.ts` |
| 言語パック（`LanguagePackDef`） | 言語 1 つの名前と、どのプラグインの文言にも足せる訳 | `core/i18n/messages.ts` |
| テーマキー（`TokenDef`） | テーマの値の名前と既定 | `core/def/theme.ts` |
| 既定のキーバインド（`KeyDef`） | キーとコマンドの組 1 つ | `store/keys.ts` |
| キーの範囲（`KeyScopeDef`） | キーバインドが効く場面の名前と、画面に出す題名と、そこに置くキーバインドが呼ぶコマンドの種類（`commandsFrom`） | `store/keys.ts` |
| ノーマライズステップ（`NormalizeStepDef`） | アクションの run のあとに、perform が変わったブックにかける処理。id を持たない | `core/def/normalize-step.ts` |
| 台帳アセンブルのときの確かめ（`CatalogCheckDef`） | ビルトインプラグインが、自分の書き足したフィールドを台帳アセンブルのときに確かめる処理。id を持たない | `core/core-catalog.ts` |
| プラグイン状態（`PluginStateDef`） | プラグインが画面の中で持つ状態 1 つの宣言 | `core/def/plugin-state.ts` |
| スクリーンの定義（`ScreenDef`） | 窓が見せる画面 1 枚の種類。開くときに渡す値の形（Zod）と、ステージを並べるか | `core/def/screen-def.ts` |
| スクリーンアレンジメント（`ScreenArrangementDef`） | 窓の、開いているスクリーンの見せ方。値の形と初めの値（持たなくてもよい）を持ち、見えているスクリーンを答える | `core/def/screen-arrangement.ts` |
| 書庫アピアランス（`LibraryAppearanceDef`） | スクリーンの中で書庫を見せる所の種類。持ち主のプラグイン状態から、今中身を見せているフォルダを答える | `core/def/library-appearance.ts` |

- 定義の種類（文言の組・言語パック・テーマキー・既定のキーバインド・ノーマライズステップ・台帳アセンブルのときの確かめを除く上の表）の一覧は `core/catalog.ts` の `PARTS` と `PartTables` だけに書き、定義の型は、その台帳のクレートが `PartDefTable` に書き足す。種類ごとの見た目のフィールド（`definePluginUi`）と定義を書く関数（`pluginKit` の `define…`）は、`ui/part-ui.ts` の `PART_UI` に種類ごとに書く
- 文言の組・言語パック・テーマキー・既定のキーバインドは、プラグインの `messages`・`languages`・`tokens`・`keys`（テーマキーはアイテムとページのタイプの `tokens` にも）に書き、`PARTS` に入れない。どれも id を持ち、機能台帳が id ごとに 1 つ並べる（アイテムとページのタイプのテーマキーは、機能台帳には並ばず、その定義オブジェクトの中にある）。同じ id は error。定義を書く関数（`kit.defineKey`・`kit.defineLanguagePack`）は `ui/part-ui.ts` の `NON_PART_DEFINES` に書く。文言の組は `pluginKit` が作る
- 定義は `defineX()` で書く。React を使わない（描き方はプラグインの見た目で結ぶ）

- core 台帳は定義の組から作り、作ったあとは変えない。作るときに表どうしの参照を確かめ、食い違えば作らない
- core の関数は使う表を最初の引数（`catalog`。core 台帳）で受け取り、アクションは `ctx.catalog` で受け取る

## 拡張ポイント

- どの定義オブジェクトの型も、種類ごとの拡張ポイントを含む。土台のファイルの定義オブジェクトの型に書くのは、土台が読むフィールド・メソッドだけ。ほかのプラグインが読むものは、読む側のプラグインが拡張ポイントに書き足す。いくつものプラグインが使う見込みのものは base が書き足す
- 拡張ポイントは `core/catalog.ts`（追加プラグインからは `matomezu/catalog`）の `PageTypeExtras`・`ShapeItemExtras<D>`・`ConnectorItemExtras<D>`・`ActionExtras`・`ThemeExtras`・`TokenExtras`・`PaperExtras`・`TextColorExtras`・`SkinExtras`・`SettingExtras`・`PresentationExtras`・`ToolExtras`・`ToolSetExtras`・`PermissionExtras`・`AnnotationExtras`・`MailExtras`・`SubjectExtras`・`ScreenExtras`・`ScreenArrangementExtras`・`EnumExtras`・`EnumValueExtras`・`ControlCenterExtras`・`MessageSetExtras`・`LanguagePackExtras`・`CommandExtras`・`DialogExtras`・`KeyExtras`・`KeyScopeExtras`・`PluginStateExtras`・`LibraryAppearanceExtras`・`WidgetExtras`・`LayoutExtras`・`PresentationViewExtras`。形とつなぐものの拡張ポイントは、置いたデータの型 `D` を、ダイアログの拡張ポイントは開くときの値の型 `A` を受ける（書き足すときも同じ型引数で書く）
- base が書き足す名前は短い名前。base 以外は `"<プラグインの id>:<名前>"`。書き足したプラグインは、自分の名前を `kit.name` で引く
- 追加プラグインが、ほかのプラグインに答えてもらう書き足しは、そのプラグインのコードとは別の連携ポイントに置く。書き足したプラグインも、答えるプラグインも、それを `import type` で読む（型だけなので変換で消える。値で読むと error）
- ビルトインプラグインどうしは、連携ポイントを作らない。同じプログラムの中で、読む側が書き足した型を共に使う
- 台帳アセンブルは、知らないフィールド・メソッドを error にしない（定義オブジェクトはそのまま機能台帳に並ぶ）。書き足したフィールドを確かめるのは、書き足したビルトインプラグインの台帳アセンブルのときの確かめ（`checks`。error は core の error の表に、warning は core の warning の表に足す）で、追加プラグインは持てない（型と台帳アセンブルの両方で止める）

## 参照の向き

- ページのタイプは、アイテム・道具の組を id で選ぶ（関係はこの選択で表す）。アクションとアノテーションの種類は、足す物・外す物だけを書く（詳しくは「ページのタイプ」「アノテーション」）
- テーマは向くテーマタイプを、ページのタイプは使うテーマタイプを書く（どちらも base が拡張ポイントに書き足したフィールド `themeTypes`）。タイプのページと中の形に使えるのは、`"all"` のテーマと、テーマタイプが 1 つでも重なるテーマで、タイプの既定のテーマ（`theme`）もその中から選ぶ。テーマを受け付けるアクションは使えないテーマを断り、データに残っていても使わない（データは消さない）。使えるかは base の `themesFor`・`themeFits` で読み、機能台帳のテーマを直に並べない
- アイテムとアクションは、ページのタイプを知らない。アイテムはアクションを知らない（アクションは付く先 `attach` に、扱うアイテムの id を書く）
- タイプの名前を見て振る舞いを分ける判定や、データの形を見てタイプを推し量る判定は作らない。使えるかは、タイプが選んだリストで決まる
- ページのタイプと、バインダが入れるタイプは、作ったあと変えない（タイプが違うページの互換は土台で定義しない）。1 枚のページに並べ方の違うものを混ぜず、並べ方が違えばタイプを分ける

## ブック

- ブックはタイプを持たない（タイプを持つのはページ）。ブックはエントリ（ページ・バインダ・読めないページ）を順に持ち、バインダは 1 つのタイプのページ（と読めないページ）だけを順に持つ。バインダの中に、バインダやフォルダは入れない
- 書庫ホームとフォルダは、ページ・バインダ・ブック・フォルダを順に持つ。ゴミ箱も同じ物を持つ。書庫ホームとゴミ箱は、どのフォルダにも入らない。ほかのフォルダ（ブック・バインダを含む）とページは、ちょうど 1 つのフォルダ（ブック・バインダを含む）に入り、上へたどると書庫ホームかゴミ箱に着く（輪にならない）。残したデータがこれを守っていなければ warning にし、ブックは読めるまま、書庫が対象のアクションは断る
- フォルダ（ブック・バインダを含む）に直に入っているエントリどうしは、名前が重ならない（ゴミ箱に直に入っている物どうしは、重なってよい）。読めないページも数える（名前の無い読めないページは数えない）
- 名前が重なって断るときは、断りの種類 `title-taken`（土台の種類なので、名前空間を付けない）を添える
- バインダの中のページは、紙のサイズと向きが同じ
- プラグインは、フォルダ（ブック・バインダを含む）の中身（`lineup`）を直にたどらず、組み直さない。読むのも変えるのも、土台の関数を通す（ページの中身がタイプの選んだアイテムかを型で示せない所の言い張りは、土台の関数に閉じる）
- 名前（`title`。1 字以上）・ロック（`locked`）は、どのブックも持つ土台のフィールド
- ブック・ページ・書庫が対象のアクションの結果は、`perform` が機能台帳のブックの形と、この節の決まり・タイプの `holds` で確かめ直し、合わなければ断る（型を言い張った所があっても、ここで止める）。行う前から在るページのタイプを変えていても断る
- 今の機能台帳で読めないページは、読めるブックの中の読めないページのエントリになる。読めないページには何もできない（宛先にする・引数で名指して動かす・消す・複製するアクションを、`perform` が `unreadable` で断る）。データには手を付けず、無くなるのはブックごと消すときだけ

## ページのタイプ

- 使えるアイテムは、タイプが `items.allowed` に並べる（データに置け、利用者も AI も置ける物）。ツールボックスにどう出すかは、アイテムの定義が決める
- タイプは、選んだアイテムに指定を渡せる（`items.options`。渡せるのは `items.allowed` のアイテムだけ。指定の形は、アイテムの持ち主が `ItemOptionTable` に書き足して決める）
- タイプは、ページがブックにどう入るかを `grouping` で宣言する。`none` のタイプのページは 1 枚ずつブックに直に入り、`binder` のタイプのページはいつもバインダに入る（スライド）
- ページを複製させるタイプは、`duplicatesPages`（base が拡張ポイントに書き足したフィールド）を宣言する。複製は、ページの中のどの深さの `id` も振り直し、つなぐものの `from`・`to` も付け替える。宣言できるのは、ページの中の物の id を指すフィールドが、つなぐものの端と、`survivesRenewedIds: false` を書いた形の中だけのタイプ（その形のあるページは複製を断る。「アイテム」の `survivesRenewedIds`）。ページの id を指すフィールドは、写しても同じページを指す
- タイプは、ページに `items` とは別の、形だけの並び（`slide`）を持たせられる。置ける形は `slide.allowed` に id で並べる（つなぐもの（`kind: "connector"`）は置けない）。この並びの形は、押し合わず、線でつながず、紙に収める決まりもかけない
- `slide` に `background: true` を書くと、その並びはページの背景（書かなければページの本体）。背景のタイプでは、ステージの `edits` が `slide` の間（背景編集モード）だけ slide の形を操作できる。「本体か背景か」の判定は `slideIsBackground` 1 つで、読む側は自分で推し量らない。背景を印刷に出すかの設定の項目 `BACKGROUND_PRINT` は、背景のタイプが `settings` に選ぶ
- 使えるアクションは、タイプが選んだ物について来る（アクションの `attach`）。タイプの `actions` は、そのタイプだけのアクションを足す `add` と、使わせない `without` だけを書く（アクションを並べる `allowed`・`defaults` は持たない）
- 道具の組は、プラグインが `defineToolSet` で持ち、タイプは `tools` で id で名指す。同じ組を名指すタイプは、同じ道具を共有する。道具の定義（`ToolDef`）のフィールドは、土台が読む `pans`・`places`・`performs` だけ。`performs` はその道具で行うアクションで、開いているページで、どれも認可ステップに止められるなら、その道具は使えず、組の次の使える道具になる。ほかの動きは、ビューが今の道具を見て決めるか、読む側のプラグインが拡張ポイントに書き足す
- データの形の外の決まり（アイテムどうしの関係）は `holds` に書く。`holds` は、ブック全体でなくページ 1 枚にかける
- タイプはページに自分のフィールドを足せる（`fields`。ページがすでに持つフィールドと同じ名前は error）。値が無ければ定義の既定で読む値は設定の項目（`settings`）にし、そのタイプのページだけのデータは `fields` にする
- タイプが選んだページの設定の項目（`settings`）とページのフィールド（`fields`）は base のアクションが受け付け、タイプの宣言した形で確かめる。ページのフィールドの受け方（受ける形と、ページへの書き方）は、タイプが決められる。タイプは、ページに問題があることを知らせられる（知らせの文言は任意）。base のアクションは、問題のあるページを書かない。断ったことを利用者に知らせるか、どう知らせるかは、呼んだ側が決める。タイプごとの作る・更新のアクションは作らない
- タイプは、ページを作るダイアログとページの設定のダイアログを id で名指せる（`dialogs`。名指さなければ base のもの）。作るほうは値を受けず、設定のほうは土台が決めた `PageSettingsArgs` を受ける。名指したダイアログがそうなっているかを型で確かめる。行うのは base のアクションで、ダイアログのために別のアクションを作らない
- ページのテーマと紙の色は、base が定義するページの設定の項目（`@matomezu/base:page-theme`・`@matomezu/base:page-paper-color`）で、タイプが `settings` に id で選ぶ。名前は設定の項目ではない
- 文字の色の値は、定義の色を、ページのテーマの `textColors`（base が拡張ポイントに書き足したフィールド。文字の色の id → 色）で変え、base が定義するページの設定の項目（`@matomezu/base:page-text-colors`。文字の色の id → 色）で上書きする。ページの設定で上書きできるのは、タイプが `settings` に選んだページだけ。さらに、利用者の設定の項目（`@matomezu/base:text-colors`）で上書きする（いちばん強い）
- 物の名前の `labelOf`（アイテムの所を参照）は、ページのタイプでは、ページの中の、形にもつなぐものにも無い物（ツリーの節など）について答える
- 可変ページにするには、タイプが `grow`（base が拡張ポイントに書き足したフィールド）を書く（無ければ可変ページにできない）。増やす向きは、利用者に選ばせる（`choices`）か、ページで効いている設定の値から決める（`sides`）か、どのページもいつも可変ページにして決まった向きへ増やす（`always`。可変ページにする・やめるは、利用者も AI も選べない）
- ページが可変ページか、どの向きへ増やすかは、ページの `grows` を直に見ず、base の `growOf` で読む（拡張ポイントでは、base が渡す増やす向き `grow`）
- 印刷区画の境目をまたいだ形を、印刷プレビューを開く前に直してもらうタイプは `printCrossing: "ask"`（base が拡張ポイントに書き足したフィールド）を書く。書かなければ、またいだまま紙の境目で切れて刷る
- ページの `slide` を持ち、中身を左・上の向きへ増やして右・下へずらすプレゼンテーション（ツリーなど）は、ずらした量（印刷区画の数）を、ページのタイプの定義の `contentOrigin`（base が拡張ポイントに書き足したメソッド。引数は `pageProblem` と同じ並び）で返す。背景のレイヤーが、同じだけずらして描くために読む。無ければ 0（ずらさずに描く）。プレゼンテーションのビューが `useStageArea` で知らせるずらした量と同じ値を返す

## プレゼンテーション

- 形の位置をデータに持たず、並べ方から決めるプレゼンテーション（ツリーなど）は、プレゼンテーションの定義に `printSheets`（base が拡張ポイントに書き足したメソッド）を書き、ページの印刷区画を数える。無ければ形の位置から数える。印刷のときだけの並べ直し（改ページなど）は、印刷の並べ方（`purpose: "print"`）で数える `printSheets` と、描く `printSheet` で同じに行い、データと編集の間の並びは変えない
- ページの文字を探させるプレゼンテーションは、プレゼンテーションの定義に `search`（base が拡張ポイントに書き足したフィールド）を書く。無ければ、そのタイプのページは探せない（開いているページがそうなら、検索のコマンドを出さない）
- ミニマップの絵は、プレゼンテーションの定義の `minimap`（base のミニマップが拡張ポイントに書き足したメソッド。書かなくてよい）が決める。書かなければ何も描かない。置いたアイテムで描くプレゼンテーション（紙など）は、形・つなぐものの定義の `minimap`（同じく書かなくてよい）に聞く。形は、書かなければ置いた四角を描き、つなぐものは書かなければ描かない。色と線の太さはミニマップが決める。つなぐもののビューが `useDrawnMinimap` で絵を置いたら、ミニマップはそのページのその種類のつなぐものを、定義の `minimap` に聞かずにその絵で描く

## アイテム

- kind を持つ（画面に置ける `shape`、2 つの形をつなぐ `connector`）
- アイテムとページのタイプの定義の `version` は、その定義が決めるデータ（置いたアイテム・ページ）の形の版。形を変えたら上げる。保存したデータに版を残し、古い版のデータを今の形に直すのに使う【未実装】
- 並べ方を知らない。持つのは自分の形・大きさ・つなぎ口と、ケイパビリティの宣言まで。ケイパビリティは `core/catalog.ts` の `CapabilityTable` に書き足して作る（土台の `connectable`・`resizable`・`nests` のほかは `<プラグインの id>:<名前>`）。土台が意味を知るのは土台の 3 つだけで、足したケイパビリティは足したプラグインの処理が読む。名前の頭は `createMatomezu` の型が確かめる。並べるのはページのタイプ
- ケイパビリティ `nests` のある形は、子の形の並び `shapes` を持てる。中に置くのは、そのページのタイプが選んだ形だけ。空の並びは持たない。子の位置は親の左上から測る
- つなぐものはページの `items` にだけ置く。端はどの深さの形でもよい
- つなぐものの定義は、置いた形との関係の決まりを自分の `holds` に書ける（タイプの `holds` とは別に、そのつなぐものの並びについて答える）
- 形を id で探すときは、どの深さの子の形も探す
- 形を並べる決まりは、同じ Frame の中の形どうしにかける。子の領域は子に合わせて広がる。子の領域の中では、押した形を縮めない
- 並べ方から描くもの（ツリーの線など）は、データに無いのでアイテムにしない
- 項目の形（`props`）は Zod。ページのデータの検査は、そのページのタイプが使うアイテムの項目を集めて組み立てる。AI には、ページのタイプごとに使えるアイテムを、そのタイプの中で見せる
- 知らないアイテムが来ても壊さない（枠だけ描き、データは消さない）。機能台帳に無いアイテム（プラグインを外したなど）がページにあってもブックは読め、データはそのまま残す。形は枠だけで描き、選ぶ・動かす・消すはできるが中身は変えられない。線は描かない。決まりの確かめでは、知らない形はつなげる物として扱う。機能台帳にあってタイプが選んでいないアイテムと、項目の形が合わないアイテムを持つページは、読めないページになる（warning にする）
- 物を直すダイアログは、定義に `edits`（base が拡張ポイントに書き足したメソッド。開くときの値から直す物を返す）を書く。開いている間、その物に編集ロックが掛かる
- その場の編集は、何も選んでいなければ始まらず、選択が替わる・開くものが変わる・道具が替わると終わる
- その場の編集の間は、選んでいる物に自動で編集ロックが掛かる。それ以外で物を直す見た目（マークダウンのソースのペインのようなテキストForm）は、書いている間 `useEditLock` を掛ける
- 形の追加と編集のダイアログ（`dialogs.add`・`dialogs.edit`）は、どちらも書かなくてよい。無ければ追加はそのまま置き、編集は「設定」を出さない。渡す値は土台が決めた `ShapeAddArgs`・`ShapeEditArgs` で、名指したダイアログがその値を受けるかを型で確かめる
- 置こうとしている物が項目の値を持っていれば、紙に置く道具は追加のダイアログを開かずにその値で置く
- 形の紙に置くための値（core のフィールドの `min` と、base が拡張ポイントに書き足した `sizeOf`・`captionWidth`）は、どれも書かなくてよい。無ければ大きさは置いたときの `w`・`h`（無ければ定義の `size`）、キャプションの幅は定義の `size.w`、`min` が無ければ大きさを変えられない
- 大きさが項目から決まる形（`sizeOf` が項目から大きさを答える形）を、大きさを変えられるようにするときは、ケイパビリティ `resizable` と `min` に加えて、定義に `resizedTo`（base が拡張ポイントに書き足したメソッド。求めた大きさを項目に写して返す）を書く。書いた形は `w`・`h` を持たず、押されても縮まない
- キャプション（形の名前として見せる文字）を持つ形は、定義の `captionProp`（base が拡張ポイントに書き足したフィールド）にその項目の名前を書く。base はその項目が変わったときだけ、見える幅まで形を広げる。`captionProp` の無い形は、`caption` という項目があっても大きさを変えない。名指した項目が `props` に無ければ error（型と台帳アセンブルで確かめる）
- 個別のテーマ（その形だけ別のテーマで描く値）を持つ形は、定義の `themeProp`（base が拡張ポイントに書き足したフィールド）にその項目の名前を書く。base は名指した項目だけをテーマの id として確かめ（そのページのタイプが使えないテーマなら置く・変えるを断る）、ほかの形の `theme` という項目は見ない。名指した項目が `props` に無ければ error（型と台帳アセンブルで確かめる）
- つなぐものはツールボックスに出さない（base が拡張ポイントに書き足した `toolbox` は、つなぐものでは `false` だけ書ける。型で確かめる）
- スクラップトレイから置ける形（スクラップフレーム）は、定義に `scrapFrame`（base が拡張ポイントに書き足したフィールド）を書く。書けるのは、スクラップのデータだけでそのまま項目になるアイテムだけ（足す項目は省けるものに限る。型と台帳アセンブルで確かめる）。スクラップはページの中身を写さず、置いたスクラップはスクラップトレイとつながらない。指す先のページがあるかは、置く・切り抜くときに確かめず、描くときに無ければ無いと見せる
- 端の形が無くなったつなぐもの（機能台帳にあるもの）は、形が変わったあとに base が消す。つなぐものの `tidy` に任せない
- 位置を自分で持つつなぐもの（手で直した途中の点など）は、端の形のほかに載る印刷区画を、定義の `printBelongingPoints`（base が拡張ポイントに書き足したメソッド）で、その印刷区画にある点として返す（線では手で直した区間の折れ目）。無ければ、端の形の印刷区画にだけ載る
- 位置を自分で持つつなぐもの（手で直した途中の点・端の固定など）は、定義に `shift`（可変ページの中身を印刷区画の単位でずらすとき）と `unpin`（形を並べ直したとき）を書く（base が拡張ポイントに書き足したメソッド）。書かなければ、中身をずらしても、並べ直しても、その位置だけが元のまま残る
- id を持つ物の、画面に出す名前は、定義の `labelOf`（base が拡張ポイントに書き足したメソッド。書かなくてよい）が返す。形は自分と自分の中身（`content`。リストの行など。子の形は除く）について、つなぐものは自分について答える。書かなければ形そのものはキャプション（`captionProp`）で呼ばれ、書いたら形そのものの名前も返す。名前が空なら、画面はその物の種類の名前で呼ぶ。名前に本文の装飾を含めてよい
- 中身のフィールド（リストの行など）は、形の定義の `content` に好きな名前でいくつでも宣言できる。ビューにはフィールドの名前ごとに渡し（`content: { フィールドの名前: [...] }`）。中の物の id の振り方は「id」の節
- 中の id を指す項目を持つ形（id を振り直した写しで参照が切れる形）は、定義に `survivesRenewedIds: false`（base が拡張ポイントに書き足したフィールド）を書く。id を振り直して写す処理は、写す物にその形があれば写さずに断る（あるかは base の `survivesRenewedIds` で読む）
- つなぐものが形に求める見た目（薄くする形・強調する形）は `ShapeMarksProvider` で渡す。つなぐものがいくつあっても求めを合わせる: 薄くするのは、どれかが薄くすると求めた形。強調するのは、内側のつなぐものから見て最初に求めた形

## 設定の項目

- 設定の項目は、値の持ち主（`holder`）を `page` か `book` で宣言する。ページが持つ項目は、ページのタイプが `settings`（id の並び）で選ぶ。ブックが持つ項目は、タイプに関係なく、どのブックも持つ
- ページの設定の値は、ページに値があればそれ、無ければ定義の既定（ブックの値には戻らない）。既定を持たない項目は、値が無ければ読む側が決める（テーマはページのタイプの既定のテーマ、紙の色はテーマの紙の色）
- ページの設定のダイアログとブックの設定のダイアログは、それぞれ、持ち主（`holder`）がそれに当たる項目のビュー（`settingViews`）を並べる（印刷プレビューの設定の項目は除く）。変えている項目は、確定の前から重ねて見せる（ダイアログの下書き）
- ブックが持つ設定の項目に `printPreview: true`（base が拡張ポイントに書き足したフィールド）を書くと、印刷プレビューの設定の項目になり、設定のダイアログでなく印刷プレビューの右サイドパネルに並ぶ
- 機能台帳に無い設定の項目（プラグインを外したなど）は、使わずにデータに残し、設定のダイアログに出さない。機能台帳にあって、ページのタイプが選んでいない項目を持つページは、読めないページになる（warning にする）
- 名前は id の 1 つだけ（`field` は持たない）。変える鍵もデータに残す鍵も設定の id で、データはブックとページの `settings` というフィールドの中に入れる（例: `settings: { "@matomezu/line:line-route": "elbow" }`）
- 利用者の設定の項目は、プラグインの `userSettings` に置く。1 つの id を、ページ・ブックの設定の項目と利用者の設定の項目の両方には使わない。利用者の設定も、機能台帳に無い項目を使わずに残す
- 土台は、自分が読む利用者の設定の項目（言語・スキン・キーバインド・参加の有効時間・有効にした追加プラグイン）を、id でなく `role` で引く。`role` を持てるのはビルトインプラグインの項目だけで、1 つの `role` は 1 つの項目だけが持つ。言語パック・スキン・キーバインドを足すプラグインは `role` を書かない（足した物は、その項目の選択肢になる）
- 利用者の設定の項目ごとに、変えるアクションを作らない（変えるのは base のアクション 1 つ）
- 機能台帳で変わる値の形（入れてあるテーマ・言語パックの並びなど）は `describe` に書き、`schema` には書かない。`schema` は保存した値を読むときの形なので、そこに書くと、プラグインを外したときに保存した値（ページの設定・ブックの設定・利用者の設定）が読めなくなる

## アクション

- 対象を宣言する（対象は下の「アクションの対象」のとおり）
- ページ 1 枚の中身だけを変えるアクションは、ページを対象にする（`page`）。ブックを対象にするのは、ブック自身を変える物と、エントリを変える物と、いくつものページをまとめて変える物
- ページが対象のアクションの `run` は、宛先のページ 1 枚を受けて返す。ページの id は変えない（ブックの並びとほかのページは変えられない）。宛先は `on` の `page` で、`on` にブックの id は書かない。無いページ・ゴミ箱のブックのページは `perform` が `no-page` で、読めないページは `unreadable` で断るので、`run` は「ページが無ければ断る」を書かない
- 機能台帳で変わる引数の形（ページのタイプが足すフィールドなど）は `describeArgs` で AI に見せ、`args` には書かない。受け付けるかは `run` が確かめる
- `run` は新しい値と結果を返す純粋な関数。対象に合わなければ null を返して断る。断った理由を AI に伝えるときは、null の代わりに `Declined` を返す（理由は AI だけに見せ、画面には出さない）。画面が断りの種類で知らせ方を変えるときは、`Declined` に種類（プラグインの id の名前空間を付けた名前）を添え、画面はその種類で文言を選ぶ。引数の形は Zod
- アクションは `perform` を通して行う
- ノーマライズステップは、ブック・ページ・書庫が対象のアクションの run のあとに、perform が変わったブック（書庫が対象なら、行う前から在って変わったブック）にかける。ビルトインプラグインだけが持てる。ノーマライズステップが書くページのフィールド（可変ページの `shift`）は、アクションの run が書かない（書けば perform が断る）
- 形を並べ直すアクションは、base の `unpinPage` をかける
- `library`・`settings` と対象の定義の種類のアクションを許すかは、コントロールセンターが決める（並べた物だけ使える）。コントロールセンターはビルトインプラグインだけが持つ（プラグイン API には出さない）。コントロールセンターは、利用者の設定の項目のうち変えさせない物を id で選べる（`fixedUserSettings`。利用者にも AI にも）
- ブックを作るアクション `book-create` は base が持ち、ブックを中身なしで、名前と入れるフォルダだけで作る。コントロールセンターの `actions` で選ぶ
- 同じ入力なら同じ結果を返す。使うのは文脈（`ActionContext`）の物だけで、時刻や乱数を直に使わない。新しい id は `ctx.newId()` で振る
- 時刻は `ctx.now`（UTC の時点を ISO 8601 の文字で。最初に行った所が 1 回だけ決め、行い直しでも同じ値）。日付は `ctx.today`（`ctx.now` の時点の、利用者の暦の日付。YYYY-MM-DD）。`now` と同じく最初に行った所が 1 回だけ決め、行い直しでも同じ値。アクションの定義が時刻や乱数を直に使っていないことを `test/rules.test.ts` が見張る
- ブック・ページ・アノテーションが対象のアクションは、付く先を `attach` に書く: `items`（そのアイテムを置けるタイプのページ）・`presentations`（そのプレゼンテーションを選んだタイプのページ）・`books: true`（ブックが対象のアクションを、どのブックにも。ページのタイプに依らない）・`pages: true`（ページが対象のアクションを、どのタイプのページにも）・`annotations`（そのアノテーションの種類を使えるタイプのページ）。どれか 1 つに当てはまれば使える。`attach` の無いアクションは、タイプの `add` で選ばれたときだけ使える
- ブックが対象のアクションは、ブックのどこを変えるかを許可スコープ（`permissionScope`）に書く（無ければ型の誤り）。`"book"`（ブック自身だけを変える。ページもアイテムもエントリも変えない）か、所を表す自分の引数の名前: `{ page }`（そのページを丸ごと変える・消す）・`{ entry }`（エントリその物を動かす・複製する・消す・名前を変える）・`{ creates }`（作るページのタイプ）・`{ pages, denied: "skip" }`（いくつものページをまとめて変える）。名前で言えなければ、引数から所を返す関数。ページが対象のアクションは、宛先のページのどこを変えるかを書く（無ければ型の誤り）: `"page"`（ページ全体。中のどの物でも）か、変える物の id が入っている自分の引数の名前（`{ item }`・`{ items }`）。名前で言えなければ、引数から変える物の id の並びを返す関数。利用者の設定が対象のアクションも、変える項目を許可スコープに書く（項目の id を鍵に持つ自分の引数の名前か、引数から項目の id を返す関数）
- `{ pages, denied: "skip" }` のアクションの `run` は、`ctx.permittedPages` のページだけを変える（認可ステップかページのタイプが止めたページは、そこに入らない）
- アクションを使えるかを決めるページのタイプは、許可スコープの所から決まる（ページが対象なら、宛先のページのタイプ。エントリなら、そのページのタイプか、バインダが入れるタイプ。作るページなら、そのタイプ）。ブックのどのページも変える所でページが対象のアクションを問うときは、ブックのどのページのタイプでも使えるときだけ使える
- `"book"` と書いたアクションは、ページのタイプで使える・使えないが変わらない。ページのタイプで決まる付く先（`items`・`presentations`・`annotations`）も、タイプの `add`・`without` も持たない（error）
- 書庫（`library`）が対象のアクションも、変えるブックを許可スコープに書く（無ければ型の誤り）。`{ book: 自分の引数の名前 }`（ブックの id）か `{ books: … }`（id の並び）で、ブックのページを含む全部を変えるなら `where: "all-pages"`（書かなければページもアイテムも変えない）。作るなら `"create"`。名前で言えなければ、引数から変えるブックと作るかを返す関数。行う前に変えるブックが分からなければ `"unknown"`
- 書庫のエントリ（どの種類でも）を変えるアクションは、ブックの代わりに `{ entry: 自分の引数の名前 }`（エントリの id）か `{ entries: … }`（id の並び）に、変え方の `where` を添える: `"all-pages"`（中の物ごと変える。ゴミ箱に入れる・消す）・`"place"`（入れるフォルダだけを変える）・`"title"`（名前だけを変える）・`"copy"`（複製する。エントリそのものは変えない）。エントリを動かすアクションは、動かす先のフォルダの id の入った自分の引数の名前を `into` に添える（書かないと、先のブックに行う前に問われない）。どのブックのどの所で問うかは、core がエントリから出す
- ブックかページが対象のアクションのうち、ページの中身でなくブックやページの扱いを変える物（ロックの掛け外しなど）には `history: false` を書く。書いたアクションは画面の履歴に入らない。ただし、ほかの窓のアクションバルクは、どれか 1 つが画面の履歴に入るアクションなら、まだ見ていない画面の履歴の段にする（その段には `history: false` のアクションの変更も入る）
- 書庫が対象のアクションの変更は、ブックの画面の履歴に入らず、書庫の画面の履歴に入る（AI とほかの窓の変更も、見えたら入る）。同じアクションバルクの中でも、書庫の画面の履歴に入るアクション（書庫が対象で `history: false` の無い物）の変更は書庫の画面の履歴の段に、ほかの変更はブックの画面の履歴の段に分ける。戻せないアクション（ゴミ箱から消すなど）と、元に戻す・やり直すで行うアクションには `history: false` を書く
- 利用者が行っても、どこかの窓の編集ロックの物を変える・消すなら `being-edited` で断るアクションには `lockedForUser` を書く。断るのは常駐だけで、画面の `perform` では断られない。断りを利用者に知らせるなら、`performConfirmed` で常駐の答えを待つ
- アクションバルクは、常駐が 1 トランザクションで書き、全部通るか全部断られる。編集ロックと認可ステップはアクションごとにかかる。AI の `perform` の 1 回は、1 アクションだけのアクションバルク。`performConfirmed` は、同じアクションバルクのほかのアクションが断られても断りを返す
- 郵便の既読（`seenAt`・`visitedAt`）のように、ほかのアクションの成否と一緒に決めないレコードの変更を行う、種類が対象のアクションには `bulk: "alone"` を書く。同じ同期の処理の中で行っても、自分だけのアクションバルクになる。成否を共にすべき物（変更提案郵便の反映と、反映したと郵便に残すアクションなど）には書かない
- 対象の定義の種類が対象のアクションの `run` は、返す物の `aiEditTickets`（並び）で AI 編集チケットを作る・閉じる・失敗にする・郵便が消えたと記す（消えたわけも添える）。対象の種類と `key` で 1 つを見分け、並びの順に当たる。常駐は key の意味を知らずに、そのとおりに残す
- 対象の定義の種類が対象のアクションの `run` は、返す物の `aiMessages`（並び。宛先のワークルームと文）で AI 間メッセージを送れる。返すのは、行う者が参加の確定した AI のときだけ（ほかで返せば perform が断る）。送り手は行った参加者。アクションバルクが断られたら送らない。宛先のワークルームに参加の確定した参加者がいなければ、常駐がアクションバルクを断る（`no-recipient`）
- 対象の定義の種類が対象のアクションは、アクションの定義の `readsBooks`（引数から、読むブックの id の並びを答える）で指したブックだけを、`ActionContext` の `books` で読むだけできる（「同じ入力なら同じ結果」の入力に入る）
- 利用者トリガートークのときに行うアクションは、アクションの定義が `runsWhenUserTalks` で名乗る（アノテーションが対象のアクションだけ。引数は受けない）。matomezu が利用者として、アノテーションのある読めるページごとに行う
- 常駐が初めて起動したときに 1 度だけ行うアクションは、アクションの定義が `runsOnceAtStart` で名乗る（引数は省いて `{}`）。matomezu が利用者として、まだ行っていない物を行い、行えたら、利用者があとで消しても作り直さない。行えなければ、次の起動でまた行う
- AI が参加を頼む（MCP の `join`）ときに行うアクションは、アクションの定義が `runsWhenAIJoins` で役を名乗る（`make-participant`・`notify-user`。役ごとに 1 つのアクションだけが名乗る）。`notify-user` の役のアクションは利用者だけが行い、AI の参加の頼みを受けたホストが、利用者トリガートークのときに matomezu が利用者として行うのと同じく、利用者として送る
- 参加者のセッションが終わったと常駐が確かめたときに、常駐が利用者として行うアクションは、アクションの定義が `runsWhenAIEnds` で名乗る（1 つのアクションだけが名乗る。対象の定義の種類が対象のアクションだけが書ける。利用者だけが行うアクション）
- アノテーションが対象のアクション（`annotations`）は、宛先のページ（`on` の `page`）とそのアノテーションの並びを受け、並びを返す。ページを変えたら断る。使えるかは宛先のページのタイプで決まり、行ったあとに、結び付く物のページで確かめる。認可ステップも通る。ブックが対象でもページが対象でもないので、許可スコープ（`permissionScope`）は書かない。`history: false` を書かなくても、画面の履歴には入らない
- ブック・ページ・アノテーションが対象のアクションは、印刷プレビューを開いているステージからは止まる。その間も行う物（印刷プレビューの設定を変えるなど）だけ、定義に `inPrintPreview: "runs"` を書く。AI とほかのステージからは止まらない。許可スコープを書いたコマンドが行う書庫が対象のアクションも、印刷プレビューを開いているステージからは止まる
- プラグインは、戻す・やり直すための逆のアクションを作らない。戻すのは base が画面の履歴の段から行う。base は、画面の履歴の段が書いた値のままの所だけを戻し、ほかの変更が同じ所を変えていれば断って、その画面の履歴の段を捨てる
- `without` に付いていないアクション、`add` にすでに付いているアクション、コマンドと道具の `performs` に表に無いアクション、コントロールセンターの `fixedUserSettings` に利用者の設定の項目でない id を書いたら、その行だけ効かず、warning を残す
- アクションを行った者は、アクションの文脈（`ActionContext`）の `actor`（アクター）で決まる。読む所は `actor.kind` を直に見ず、`isAI`・`isUser` を通す
- 「アクションの対象」: 土台の 5 つ（`library`・`book`・`page`・`settings`・`annotations`）か、対象の定義が足した種類の id。種類のデータは「レコード」で、1 件が 1 つのまとまり（`id` を持つ）。core は中を読まず、形は定義の `record`（Zod）で確かめる（定義が `check` を持てば、形のほかの確かめも、そこで行う）。探す・並べるのに使う値は、定義が索引キーとして宣言する（条件と並びに書けるのは索引キーだけ）
- 言葉で探せる種類は、対象の定義に `searchTexts`（題 `title` と本文 `body`）を書く。同じレコードなら同じ文字を返す（時刻や外の状態を見ない）。書かない種類は、横断検索で探されない
- 種類が対象のアクションは、`on` の `record` で指した 1 件（指さなければ新しく作る。`run` が受けるのは `"none"`）を受け、新しい 1 件か、消すなら `"removed"` を返す。宛先のほかのレコード（同じ種類か、アクションの定義の `writes`（種類の id の並び）に書いた種類）を消す・変えるなら `others` で返す（ほかの種類は perform が断る）。1 アクションが変えるのは `on` の 1 件と `others` を合わせて決まった数まで（`RECORDS_MAX`。アクションバルクの合計には上限を置かない）で、編集ロックと認可ステップの `keeps` は変える全部に、それぞれの種類でかかる。アクションの対象と `writes` に書ける種類は、アクションと同じプラグインの種類か、持ち主のプラグインが対象の定義の `writableBy`（プラグインの id の並び。書かなければ、ほかのどのプラグインにも許さない）にそのアクションのプラグインを書いた種類だけ（ほかは台帳アセンブルが error にする）。`id` は変えず、作るときは今ある `id` と重ならない（core が見る）。レコードにゴミ箱と画面の履歴は無い
- 同じ種類の重なりなど、ほかのレコードを読んで確かめるアクションは、読む物を `reads` で、引数・行う者・宛先のレコードの id から答え（id で 1 件・索引キーの条件に合う物・その索引キーだけ）、答えた物だけを `ctx` から読むだけで受け取る。中身が要らないときは、索引キーだけを読む。宛先のレコードが指す先（`refers`）は、`reads` に書かなくても読める
- 定義の `numbered` を書いた種類のアクションは、`ctx.number(区切り)` で次の番号を受け取る。番号は常駐が決め、行い直しでも同じ値で、区切りごとに連番、消しても使い回さない。番号を振る種類は `writes` に書けない
- 常駐（ホスト）が読む種類（参加者・ワークルーム）は、対象の定義の `role` で名乗る。常駐は役（対象の定義の `role`。利用者の設定の `role` とは別）で種類を引き、読むフィールドは core が取り決める（`SUBJECT_ROLE_FIELDS`。台帳アセンブルのときに確かめる）。ホストが base の種類の id を名指さない（一度きりのデータの移し替えは除く）
- 種類が対象のアクションを許すのは、コントロールセンターの `subjects`（種類の id の並びか `"all"`）。対象の種類と `writes` の種類が全部許されたアクションだけが使える
- 残したレコードの種類が機能台帳に無い・形が合わない場合は、データに手を付けず warning にする（定義の `check` が返した warning も同じ）

## コマンドとキー

- コマンドは 2 種類。ステージで呼ぶコマンド（`defineCommand`。文脈にステージとブックがある）と、スクリーンから呼ぶコマンド（`defineScreenCommand`。文脈に呼ばれたスクリーンがあり、ステージとブックは無い）。ステージを並べないスクリーンがカレントスクリーンの間は、ステージで呼ぶコマンドのキーは効かない（そこで使うコマンドは、スクリーンから呼ぶコマンドにする）。ダイアログと右クリックのメニューも、呼ばれた所（ステージかスクリーン）で開く。キーの範囲は、ステージで呼ぶコマンドの範囲かスクリーンから呼ぶコマンドの範囲かを宣言する（`commandsFrom`）。スクリーンから呼ぶコマンドの範囲には、スクリーンから呼ぶコマンドのキーバインドだけを置く（ステージで呼ぶコマンドの範囲には、どちらも置ける）。ステージに属さない要素（土台の `dialog`・`menu`・左サイドパネルなど、ステージを並べないスクリーンでも出る物）が名乗る範囲は、スクリーンから呼ぶコマンドの範囲にする。スクリーンから呼ぶコマンドは、ブック・ページ・アノテーションが対象のアクションを行わない
- アクションを行うコマンドは、行うアクションを `performs` に書く。どれかが、コマンドの許可スコープの所（ブック・ページ・アノテーションが対象でなければコントロールセンター）で使えなければ、土台はそのコマンドを出さない（メニュー・右クリックのメニュー・ツールボックス・キーのどれからも）。どれも認可ステップに止められるなら、土台はそのコマンドを出したまま押せなくする。`when` は、出すコマンドの中で決める。キーは、今使えるコマンドのキーバインドのうち、狭い範囲から先に見つかった物が効く。同じ範囲・同じキーのキーバインドは捨てずに並べ（利用者 → ビルトインプラグイン → 追加プラグインの id の順。ビルトインプラグインどうしで同じ範囲・同じキーは error）、効くのはその先頭の 1 つだけ。先頭がその場で使えなければ、同じ範囲のほかの物は見ずに次の範囲の同じキーを探す（使える物が無ければ何もしない）。探すのは、焦点のある要素から外へ、名乗った範囲を狭いものから先に。そのあとで土台の範囲とプレゼンテーションの範囲を探す: プレゼンテーションが名乗った範囲（プレゼンテーションの定義の `keyScope`）は、カレントのステージがそのプレゼンテーションで描いている間、`stage` の前に探し（ダイアログ・右クリックのメニュー・道具のアイコンが開いている間は探さない）、`global` は、そのどれも開いていないとき、`stage` の次に探す。右クリックのメニューが開いている間は `menu` を、道具のアイコンが開いている間は `picker`（ステージで呼ぶコマンドの範囲）を探す。ステージを並べないスクリーンがカレントスクリーンの間は、`stage`・`global`・プレゼンテーションの範囲を探さず、`screen` を探す。テキストForm と、焦点のあるボタン・リンクの中で、その要素に任せるキー（テキストForm は Escape と 1 行のテキストForm の Enter のほか、ボタン・リンクは Space と Enter）を効かせるには、その要素自身が名乗った範囲にキーバインドを置く（ほかの範囲のキーバインドは効かない。ボタン・リンクで効かせられるのは Enter だけ）
- ドラッグの間や、一時に出した物（スタンド・ツールボックスのシェイプパネルなど）を開いている間だけの取り消し（Escape）は、キーバインドにせず、その間だけ直に受けてよい。終わったら受けるのをやめる
- ブックかページが対象のアクションを行うコマンドは、許可スコープ（`permissionScope`）を書く（無ければ型の誤り）。`"book"`・`"opened-page"`（開いているページ）・`"selection"`（選んでいる物。形の中身やページのフィールドの中の物も含む）、`{ page }`（ページの id が入っている自分の引数の名前。右クリックしたページのように、引数が所を決めるとき）・`{ entry }`（エントリの id が入っている自分の引数の名前）・`{ creates }`（作るページのタイプの id が入っている自分の引数の名前。タイプをまだ選んでいなければ、どれか 1 つのタイプで作れれば使える）か、呼ばれた場所の様子と引数から所を返す関数。書庫が対象のアクションを行うコマンドも許可スコープを書いてよく、書けば、そのアクションを開いているブックのその所を変える物として問う

## 参加者

- 参加者リストは、ワークルーム・参加者・管理者の印の 3 つの対象の定義（base。レコード）。受け入れ済みの参加者は入っているワークルームの `id` を持ち、空室は入っている参加者がいないワークルーム（ワークルームの側には持たない）。AI が行えるのは参加の要求だけで、ほかは利用者だけ（`userOnly`）。ワークルームの名前は重ならず、ワークルームに入る参加者は 1 人で、人のいるワークルームは、その参加者も外すアクションでなければ消せない。重ならないことはアクションが `reads` で確かめ、生きているか（時刻で決まるので、アクションの入力に無い）は、受け入れのダイアログと join（ホスト）が見る。いる参加者を外して入れる・ワークルームを消すは、外す参加者と、作る・消すワークルームまで、1 つのアクション（1 トランザクション）で変える。外すのは、引数で渡した参加者がそのワークルームにいるときだけ。指す先のワークルームが無い管理者の印は「無い」として読み、書き換えない
- 参加者は、AI のセッション 1 つがワークルームに入るための記録。「生きている」かは、常駐が記録した最後に呼ばれた時刻と、利用者の設定（参加の有効時間）で決める。判断は core の 1 つの関数で行い、画面もホストもそれを使う
- 受け入れても、AI のフック（Claude Code の `UserPromptSubmit` など）が参加を伝えるまでは準備中で、生きていない。準備中かは常駐だけが決め、画面は常駐から受ける。準備中の参加者の id を AI が名乗っても、参加者として数えない（最後に呼ばれた時刻などを残さない）。参加が確定していない AI（参加者でない・要求中・準備中。アクターの `workroom` が `"none"`）は、ブック・ページ・アノテーションのほかが対象のアクション（参加を頼む役を除く）を断られる（`not-allowed`、理由は `not-joined`）。ブック・ページ・アノテーションが対象のアクションは参加を問わない。セッション id を join で運ぶ AI は、受け入れた時点で準備中でなくなる

## 認可ステップ

- 認可ステップ（`PermissionDef`）は、止めるだけで、許すことはしない（使えるかはページのタイプかコントロールセンターが決める。認可ステップを足しても、できることは広がらない）
- 認可ステップが受ける問いと確かめには `kind` が付く。core がアクションの対象から決めて渡す: 行う前の問いは、ページ・アノテーションが対象なら `"page"`（宛先のページと、それを入れているバインダとブックを近い順に渡す。宛先のページが分からなければ `"folder"`）、ブック・書庫が対象なら `"folder"`（ブック）、対象の定義の種類なら `"record"`。行った後の確かめは、変わったブックごとの `"folder"` と、`"record"`。ステップは受け取った `kind` で自分が読む物だけを扱う
- 行う前は、アクションの許可スコープから出した所で聞かれ、止めるかを答える（扱うエントリと、作るページのタイプでも聞かれる）。この答えは出し方（押せなくするなど）に使う（`denied: "skip"` のアクションでは、変えるページも決める）。書庫が対象なら、変えるブックごとに聞かれ、どれかのブックで止めれば perform は断る。作るブックは、空のブックで聞かれる（id と名前は問うためだけの物で、見ない）。`"unknown"` なら、行う前には聞かれない
- データを守るのは、行った後に、前と後のブックの変化で確かめる方（行う前に所が分からない・粗いときも、ここで止まる）。書庫が対象のアクションでは、無くなったブックと増えたブックも確かめる。置き場所が変わったブックも確かめる（ブックの値が変わらなくても。ブックを中に持つフォルダごと変わったときの、中のブックも）
- 同じ入力なら同じ答えを返す（アクションと同じ。時刻・乱数・外の状態を見ない）
- 止めたら `perform` は、止めた認可ステップの id を添えて断る。書庫が対象のアクションでは、止めたブックの id も添える。画面の各機能は、その id を見て、薄くする・消す・色を変えるなどを自分で決める
- レコードが指すほかのレコードは、対象の定義の `refers` が答える。`refers` の先頭は、そのレコードが属するレコード（チケット履歴ならチケット）で、横断検索の当たりが開く先に使う。認可ステップが「指す先が閉じている」などで止めるときは、行った後の実際のレコードの参照で守る（アクションの引数ではなく）。指す先は core が読む（「アクション」の `reads`）
- レコードにもロックを掛けられる。対象の定義に `lockable`、ロックの掛け外しをするアクションに `lockSwitch` を書く（base が拡張ポイントに足した名前。`locked`（`true`、省ける）は種類が `record` に書く）。ロック中のレコードは、`lockSwitch` のアクションのほかを断る。`lockSwitch` のアクションが、対象の種類のレコードで変えてよいのは `locked` だけで、ほかも変えれば断る（`writes` は持てない）
- ロックは base の認可ステップ（`@matomezu/base:lock`）。アクションの `run` はロックを確かめない。ロックを外すアクションは、レコードのロックも含めて利用者だけ（`userOnly`）。ロックはアノテーションが対象のアクションを止めない。ロックの掛かったブックは、ゴミ箱にも入れられない。入れるフォルダを変えるだけなら止めない（フォルダの間を動かせる。名前は変えられない）。ロックの掛かったページも、ほかのブックへ動かせるが、名前は変えられない
- アノテーションが対象のアクションの問いには、変える所の物の id（`where` の `ids`）を渡さない

## アノテーション

- 種類は、プラグインが定義（`AnnotationDef`）で足す。ページのタイプは `annotations.without` で種類を外す（書かなければ、どの種類も使える）
- 結び付けられるのは、ページの中の id を持つ物（アイテム・リストの行・節など）で、ページそのものではない
- 結び付く物が全部無くなったアノテーションは残らない（Undo で物が戻っても、アノテーションは戻らない）。ブックをゴミ箱から消すと、そのブックのアノテーションも消える
- 種類が機能台帳に無い・形が合わない・タイプが外した種類・結び付く物がブックに無いアノテーションは、データに残して効かない物にし、warning にする
- 例外として、利用者が常駐からプラグインを外したときは、そのプラグインの種類のアノテーションを消す（ページの中身ではなく、外したプラグインの物を残しても使い道が無いため）。プラグインを入れずに起動したときは消さない
- AI の応えを待つかは、種類の定義の `awaits` が決める。待つ物を数えて AI に知らせるのは matomezu で、種類は数えない・知らせない
- AI に知らせるとき、その物を見分ける文は、種類の定義の `aiBrief` が答える（書かなくてよい。無ければ種類の id だけで見分ける）。利用者が書いた文はそのまま、決まった言葉は英語で返す。知らせる行にするのは matomezu
- 種類は期限を持てる（`expiresAt`。今の時刻を見ず、時点を返す）。期限の過ぎたアノテーションは残らず、画面にも出さない。利用者が直している物（編集ロック）は残す
- 送信トレイでの出し方（付けた時点・行の文・取消のアクション・押したときに開く右サイドパネルの中身）は、種類の定義の `listed`（base が拡張ポイントに書き足したフィールド。書かなくてよい）が答える。行の絵は、見た目の側でスロット `@matomezu/base:annotation-icon` に置くウィジェット（`defineAnnotationIcon`）が描く

## 郵便

- 種類は、プラグインが定義（`MailDef`）で足す。郵便箱は 200 通までで、超えたら古い既読の郵便から消す。郵便は base の対象の定義 `mail` のレコード 1 件 1 通で、届いた順を `order` で決める。郵便箱は、その種類のレコードの並び。郵便の形と、郵便の種類での確かめは base が持つ（core は郵便を読まない）
- 郵便の行き先は、送るときには確かめない。開くときに無ければ、無いと見せる
- 既読は 2 つ。利用者が郵便を見た時点（`seenAt`）と、行き先を見た時点（`visitedAt`）。どちらも利用者のアクションだけが付ける
- 種類が機能台帳に無い・形が合わない郵便は、データに残して warning にする
- 郵便を画面に出すときの題と本文は、種類の定義の `shown`（base が拡張ポイントに書き足したフィールド。書かなくてよい）が答える
- 郵便が消えるとき（上限で古い郵便を消す・利用者が消す）の AI 編集チケットの直しは、種類の定義の `ticketOnRemoved`（base が拡張ポイントに書き足したメソッド。郵便と消えたわけを受ける。書かなくてよい。無ければ直さない）が答え、郵便を消すアクションが `aiEditTickets` に入れて返す
- 郵便の種類の AI 向けの説明は、種類の定義の `aiDescription` に書く
- AI に郵便の目次を見せるときの題は、種類の定義の `aiBrief` が答える（書き方は「アノテーション」の `aiBrief` と同じ。書かなくてよい。無ければ種類の id だけで見分ける）。1 行に整えて切るのは matomezu

## スクリーン

- 窓に出す画面は、スクリーンの定義にする。開くときに渡す値は、画面の場所（URL）に入る
- 同じ定義・同じ渡す値でも、別の 1 枚として開ける。スクリーンが持つ状態は、スクリーンの範囲のプラグイン状態にする（ビューの中だけの一時の状態は「コードの書き方」の「データとビュー」）
- 開いている 1 枚の渡す値は、別の 1 枚として開かずに替えられる（同じ 1 枚のままで、スクリーンの範囲のプラグイン状態は残る）。値が替わったときの状態は、描く側が今の渡す値の物か確かめる
- スクリーンアレンジメントが答える「見えているスクリーン」は、描いているスクリーンと同じにする（まだ見ていない変更が見えたかと、AI への知らせが、この答えで決まる）
- 見えているスクリーンを決めるのに要る値（分けて並べるスクリーンの並びなど）は、スクリーンアレンジメントの値にする。窓が持ち、画面の場所に入る。描き方にだけ使う値（高さの割合など）は、プラグイン状態にする
- ステージを並べるスクリーンの定義は 1 つだけ（2 つなら error）。窓を開いたときのスクリーンアレンジメントを名乗れるのも 1 つだけ（2 つなら error）
- スクリーンの定義は、開いたままにする枚数を名乗れる（`maxOpen`。ブックスクリーンは 2）。土台は、超えた分を、カレントにしたのが古い物から閉じる。AI が画面に出すとき（show）も同じ決まりを通す
- 書庫を見せるスクリーンの定義は、見せることのある書庫アピアランスを `libraryAppearances` に id で並べ、そのうち今見せている物を `shownLibraryAppearances` で答える（無ければ、並べた物を全部いつも見せている）。描いたまま隠している物は答えに含めない。書庫アピアランスの `shownFolders` は、描いている物と同じに、今中身を見せているフォルダを答える。どちらも、聞かれたスクリーンの、自分のプラグイン状態だけを読んで答える。AI とほかの窓の書庫の変更は、見えているスクリーンが今見せているフォルダの中で変わった物なら、見えたとする

## 列挙

- 列挙は、プラグインが宣言し（`EnumDef`）、宣言した自分とほかのプラグインが値（`EnumValueDef`）を足す。値は宣言の id を `enum` で名指し、宣言は値を知らない
- 値はデータだけで、メソッドを持たない。土台が持つのは `id`・`title`（文言の鍵）・`aiDescription` と、宣言の `value`（値の `data` の形。Zod）で、`data` を読んで振る舞いを決めるのは宣言したプラグイン
- 列挙の値は `enumValuesOf` で読み、機能台帳の `enumValues` を直に並べない（宣言の無い値が混じるため）
- 値の絵は、値を足したプラグインが見た目の側で結ぶ（`enumValueIcons`。データには持たない）。絵を読むか、無いときにどう描くかは、宣言したプラグインが決める
- 列挙の値の id をデータに残すときは、schema では字だけを確かめ、ある・合うかはアクションが確かめる。機能台帳に無い値は、データに残し、どう扱うかは宣言したプラグインが決める
- 宣言が機能台帳に無い値は、その値だけ効かず warning（持ち主は値を足したプラグイン）。`data` が宣言の `value` に合わない・id が重なるのは error
- 列挙の値を受けるアクションの引数は、`describeArgs` が値の id と `aiDescription` を並べて AI に見せる（「アクション」）

## AI に見せる

- AI（MCP）には、アクションを 1 つずつ MCP 公開ツールにしない。決まった MCP 公開ツールで渡す: 今使えるアクションとアイテム・アノテーションの種類・ページのタイプ・郵便の種類・対象の定義・テーマ・代表色・文字の色・言語・スキン・利用者の設定の項目の定義を、目次と、id を渡して取る全文で返す `actions`（引数なしの答えに今の warning も。「構造とクレート」の「warning」）と、アクションを行う `perform`。ほかは読む MCP 公開ツール（`view`・`list_books`・`read_folder`・`read_book`・`read_page`・`read_records`・`search`・`read_settings`）と `show`、参加を頼む `join`、ほかの AI に送る `send_message`。`read_records` は、対象の定義のレコード（郵便も）を、目次（id と 1 行）と、id を渡して取る全文で返し、索引キーの条件で絞れる。`search` は、対象の定義のレコードを言葉で探す。追加プラグインを足し・外しても、MCP 公開ツールの一覧は変わらない
- MCP 公開ツールの引数の決まりは、inputSchema で言える物は inputSchema に書き、呼ぶ所で別に確かめない（アクションの引数は、これまでどおりアクションの `args` と `run` が確かめる）
- AI に見せる対象の定義は、`aiBrief`（レコード 1 件の 1 行。書き方は「アノテーション」の `aiBrief` と同じ）を書いた種類だけ。`actions` の対象の定義にも、`read_records` にも、`search` にも、その種類だけが出る（書かない種類のレコードは、アクションの引数や `on` で名指されるだけ）。`aiListed` で既定の目次に載せるかを、`aiOrder` で目次の並びを決める（どちらも書かなくてよい）。`aiBrief` と `aiListed` が読めるのは、そのレコードとその指す先（`refers`。読み方は「アクション」）だけ。`aiListed` を書いた種類は、載せない物が何か（英語）も書き、`actions` の対象の定義で見せる（AI は `read_records` と `search` で、載せない物も取れる。`search` は既定では載せない物を探さない）
- AI の `read_page` には、ページの形を描いた位置と大きさを、プレゼンテーションの定義の `aiPlaced`（base が拡張ポイントに書き足したメソッド。書かなくてよい）が答えて添える。書かなければ添えない
- アクションは全部 AI に見せる（利用者の設定のアクションも。行えるかは画面と同じく、コントロールセンターが決める）。ただし、利用者だけが行うアクション（`userOnly`）は見せず、AI が頼んでも断る。利用者の設定の項目の `userOnly` も同じく、AI に見せず（AI が読む設定にも出さない）、AI が変えようとしても断る
- MCP で AI に見せるもの（アクション・アイテム・タイプの名前、アクションの説明、断った理由の文）は英語に固定し、利用者の言語に合わせない。名前は英語の文言（`en`）で引く
- AI 向けの説明（英語）は、アクションの定義の `aiDescription` に書く（どう変わるか・何を返すか・断る場合）。追加プラグインも自分のアクションの説明を書く
- アノテーションの種類の AI 向けの説明（英語）は、種類の定義の `aiDescription` に書く（何のための物で、AI がどう応えるか）。追加プラグインも書く
- 認可ステップが止めたときは、止めた認可ステップの id と、その定義の `aiDescription`（英語。何がなぜ止めたか）を AI に返す
- 文字の色の意味（英語）は、文字の色の定義の `aiDescription` に書く。本文の装飾の書き方は、本文の項目の形の説明（`describe`）で AI に見せる
- 背景のタイプのページを AI に見せるときは、背景の形の図形の情報（位置・大きさ・形の種類など）を見せず、背景があることと、背景の形の名前（形の定義の `labelOf`）だけを見せる

## テーマ

- データを変える処理（アクション・ノーマライズステップ）と並べ方の計算（紙の上の位置や大きさを決める計算）は、テーマの値を引かない（テストが見張る）。その計算が前提にする字の大きさ・字体など（箱の字の幅を測る字など）はテーマキーにしない。そのほかの見た目なら、色・線・影・角の丸みのほか、字の大きさや余白もテーマキーにしてよい。描いたあとに測って決める物（印刷プレビューで紙に切る所など）は、テーマで変わってよい
- アイテムとページのタイプは、自分の使うテーマキーと既定（共通のテーマキー `fallback` か値 `value`）を宣言する。テーマキーの宣言は 1 か所だけ
- テーマキーの宣言は、テーマの id ごとの値（`themeValues`）も持てる。base のテーマでの値は、そのテーマキーを宣言したプラグインが書く。base のテーマは、ほかのプラグインのテーマキーを名指さない（テストが見張る）
- いくつものアイテムが共に使うテーマキー（8 つの形の塗りなど）は、アイテムでなくプラグインが持つ（`kit.plugin({ tokens })`。id は `kit.name` で長い形に書く）
- ページを描くのに使うテーマキーは、タイプのテーマキーと、タイプが置けるアイテム（`items.allowed` と `slide.allowed`）のテーマキーと、そのアイテムの持ち主のプラグインが持つテーマキー
- テーマは知っているテーマキーだけを上書きする（文字の色はテーマキーではなく、base の `textColors` で変える。文字の色の値は、ステージがブックの要素に置く CSS 変数 `--text-color-*` に入る）
- テーマの上書き（`tokens`）は、宣言の `themeValues` より強い。base 以外のプラグインのテーマは、ほかのプラグインのテーマキーを長い id で書いて上書きしてよい
- テーマキーに書いてよい値に決まり（決まった言葉の一覧・px の長さなど）があるビルトインプラグインは、テーマキーに書かれた値（テーマの上書きと `themeValues`）を台帳アセンブルのときの確かめ（`checks`）で見て、合わない値は warning にする（warning は書いた者のもの。テーマの上書きはそのテーマの持ち主、`themeValues` はテーマキーを宣言したプラグイン）。値を読む見た目と確かめは、同じ読み方をする
- テーマキーごとに light と dark の値を持てる。両方を書いたテーマキーは、利用者の OS の明暗で切り替える。明暗で違う値にできるのは色だけで、色でないテーマキーは宣言に `shades: "one"`（明暗で同じ値だけ）を書く。`shades: "one"` のテーマキーに明暗で違う値を書いたテーマは、台帳アセンブルが warning にする（warning は書いた者のもの）
- プラグインの見た目では、自分が宣言したテーマキーを `--<名前>` の CSS 変数で使う（例: テーマキー `@foo/stars:star-fill` → `var(--star-fill)`）。matomezu が、そのプラグインのアイテムとプレゼンテーションを描く要素に、そのプラグインのテーマキーだけを短い名前で置く（ほかのプラグインのテーマキーは置かないので、ぶつからない）。テーマキーの名前は `theme-`・`skin-` で始めない（土台の CSS 変数とぶつかるため。台帳アセンブルが確かめる）
- 土台のテーマキー（`accent`・`paper`・`text` など）は、どこでも `--theme-<名前>` で使う
- テーマキーの値を置く中の CSS 変数の名前は、matomezu の中だけのもので、開発者は書かない。ビルトインプラグインの CSS が参照するテーマキーが、宣言したテーマキーにあることをテストが見張る
- base のコンポーネントがテーマキーで見た目を受けるとき（`MarkdownDocumentView` など）は、自分が宣言したテーマキーを使う決まりの例外として、テーマキーの並び（短い id と既定）を base が出し、そのコンポーネントを使うページのタイプが `tokens` にその並びを並べる。ブックの外でコンポーネントを描く所は、同じ名前の CSS 変数を自分で置く。コンポーネントが読む名前が並びにあることを、テストが見張る

## id

- 1 つのインスタンスの中で、種類ごとに一意。データに残る id は、ほかのマシンやほかの人の matomezu でも同じものを指す
- プラグインが足す物の id は `<プラグインの id>:<名前>`（例: `@foo/stars:star`・`@matomezu/box:shape-box`）。ビルトインプラグインも同じ。定義の種類・テーマキー・ウィジェット・スロット・キーの範囲・メニュー・右クリックのメニュー・ケイパビリティ・テーマタイプ・その場の編集の名前のどれも
- 名前に使える字は英小文字・数字・`-` だけで、先頭は英小文字（kebab-case）。プラグインの id（npm のパッケージ名。ビルトインプラグインは `@matomezu/<名前>`）は `:` を含まないので、区切りを見誤らない
- `:` の無い名前は土台の言葉（スロットの `root`、キーの範囲の `stage`・`dialog`・`menu`・`picker`・`global`・`screen`、土台のテーマキーの `accent` など）。土台のキーの範囲は、題名（土台の文言）と、どちらのコマンドの範囲かも土台が持つ。土台の文言の組と言語パックの id だけは `matomezu:<名前>`（`matomezu:messages`・`matomezu:en`）
- スロット・メニュー・右クリックのメニュー・ケイパビリティ・テーマタイプの名前は、`core/catalog.ts`（`SlotTable`・`MenuTable`・`ContextMenuTable`・`CapabilityTable`・`ThemeTypeTable`）に書き足して作る。土台の言葉のほかは `<プラグインの id>:<名前>` で、渡したプラグインの id で始まるかを `createMatomezu` の型が確かめる。スクリーンとスクリーンアレンジメントの定義の id は、書き足さなくてもそのままスロットになる
- プラグインは自分の物を短い名前で定義する。プラグイン API の `pluginKit(プラグインの id, 文言)` が返す定義の関数（`kit.defineShape` など）が頭を付け、返した定義の id は長い形（型も）。自分の物は返した定義（`STAR.id`）か `kit.name(名前)` で名指し、ほかのプラグインの物は長い id で書く
- その場の編集の名前（`setEditing` に渡す名前）は、表に書き足さず `kit.name(名前)` で作る。ただの文字を渡さない
- 台帳アセンブルは、どのプラグインの物も、id がそのプラグインの id と `:` で始まり、名前が決まりの字だけかを確かめる（ビルトインプラグインも例外にしない）
- コマンド・ページのタイプ・列挙の値のアイコン（`commandIcons`・`pageTypeIcons`・`enumValueIcons`）は、自分の物にだけ付けられる（ほかのプラグインの物に付けたら、台帳アセンブルが error にする）
- ブックとフォルダの id は uuid。書庫ホームの id は、決まった値。新しく振るページの id も uuid。エントリの id は、ブックの中で重ならない（バインダの中のページと、読めないページも含めて）。ページとフォルダ（ブック・バインダを含む）の id は、書庫の全部で重ならない（ページは id だけで指せる）。プラグインは、ページとバインダの id を決めない（足すときに土台が振る）。ページの中で作る物（アイテム・その中身・ページのフィールドの中の物）の id は、`ctx.newId` から、そのページの中で重ならないように振る（ブックのほかのページの物と重ならない事は、土台が守る）。ホストとのやり取りの URL に入れるときは、URL エンコードする
- アクションの名前は「対象-動き」（例: `page-add`・`line-connect`）
- 文言の鍵の決まりは「コードの書き方」の「文言」
