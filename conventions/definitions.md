# 定義と機能台帳

機能は、定義（Def）を機能台帳に足すことで増やす。定義はどれもプラグインが持ち込む。

## 定義の表

| 表 | 何か | 置き場所 |
|---|---|---|
| ブックのタイプ（`BookTypeDef`） | ブックのデータの形・並べ方の決まり・使うアイテムとアクションの選択 | `core/def/book-type.ts` |
| アイテム（`ItemDef`） | 名詞。データに残り、画面に置かれるもの（箱・ひし形・線など） | `core/def/item.ts` |
| アクション（`ActionDef`） | 動詞。データを変える唯一の入口 | `core/def/action.ts` |
| テーマ（`ThemeDef`） | ブックの中身の見た目 | `core/def/theme.ts` |
| スキン（`SkinDef`） | アプリの枠の見た目（見る人の設定） | `core/def/skin.ts` |
| 紙（`PaperDef`） | ページに置く紙の大きさ | `core/def/paper.ts` |
| 設定の項目（`SettingDef`） | ブックやページに持たせる 1 つの値（線の既定の通り方など） | `core/def/setting.ts` |
| 見せ方（`PresentationDef`） | ブックをステージにどう見せ、どう触るか（紙など） | `core/def/presentation.ts` |
| コマンド（`CommandDef`） | 画面の入口（ボタン・メニュー・キーから呼ぶ） | `store/commands/def.ts` |
| ダイアログ（`DialogDef`） | 開くダイアログの id | `store/dialogs.ts` |
| 文言（`MessageSet`） | 画面に出す文と訳 | `core/i18n` |

- 定義の種類（文言と言語を除く上の表）の一覧は `core/catalog.ts` の `PARTS`（欄の名前・機能台帳の段・誤りの文の名前）と `PartTables`（id の表）だけに書く。定義の型は、その段の層が `PartDefTable` に書き足す（core の種類は `core/core-catalog.ts`、store の種類は `store/plugin.ts`）。プラグインの欄（`PluginParts`）・機能台帳の core と store の段・id の頭と重なりの検査は、この一覧から作る。種類ごとに意味の違う見た目の欄（`definePluginUi`）と定義を書く関数（`pluginKit` の `define…`）は、`ui/part-ui.ts` の `PART_UI` に種類ごとに書く（種類が抜けると型の誤り。書いた欄と関数があることはテストが確かめる）
- 定義は `defineX()` で書く。React を使わない（描き方はプラグインの見た目で結ぶ）
- 機能台帳の core の段は定義の組から `buildCoreCatalog` で作り、作ったあとは変えない。`checkCoreCatalog` が表どうしの参照を確かめ、食い違えば作らない
- core の関数は使う表を最初の引数（`catalog`。機能台帳の core の段）で受け取り、アクションは `ctx.catalog` で受け取る

## 参照の向き

- ブックのタイプは、アイテム・アクション・テーマ・道具の組を id で選ぶ。関係はこの選択（リスト）で表す
- アイテムとアクションは、ブックのタイプを知らない。アイテムはアクションを知らない（アクションは付く先 `attach` に、扱うアイテムの id を書く）
- タイプの名前を見て振る舞いを分ける判定や、データの形を見てタイプを推し量る判定は作らない。使えるかは、タイプが選んだリストで決まる
- タイプが違うブックの互換は土台で定義しない。1 枚のページに並べ方の違うものを混ぜず、並べ方が違えばタイプを分ける

## ブックのタイプ

- 使えるアイテムは、タイプが候補（`allowed`。データに置ける物）と既定（`defaults`。ツールボックスに出す物）を持つ
- 使えるアクションは、タイプが選んだ物について来る（アクションの `attach`）。タイプの `actions` は、そのタイプだけのアクションを足す `add` と、使わせない `without` だけを書く（アクションを並べる `allowed`・`defaults` は持たない）
- 名前（`title`）は土台の言葉で、どのタイプのブックも持つ（空でもよい。空なら画面はタイプの名前で呼ぶ）。欄は機能台帳が足し、タイプは schema に名前・テーマ・紙の色を書かない（E025）
- 道具の組は `tools` で名指す（`core/tools.ts`）。同じ組を名指すタイプは、同じ道具を共有する
- データの形の外の決まり（アイテムどうしの関係）は `holds` に書く。アクションの結果が守らなければ断り、読むときに守らないブックは捨てる
- ブックが対象のアクションの結果は、`perform` が機能台帳のブックの形（`bookSchema`）と `holds` で確かめ直し、合わなければ断る（型を言い張った所があっても、ここで止める）
- ページを持つブックを変える土台の関数は、渡されたブックの型のまま返す（`<B extends PagedBook>`）。ページを替えるのは `putPage` で、ページの中身がタイプの選んだアイテムかを型で示せない所の言い張りはここに閉じる。プラグインはブックを `{ ...book, pages }` で組み直さない
- タイプだけの設定の項目は `settings`（book・page・settle）に宣言する。base の `book-update`・`page-update` が受け付ける。タイプごとの更新のアクションは作らない
- ブックのテーマと紙の色は、base が定義する設定の項目（`@matomezu/base:book-theme`・`@matomezu/base:book-paper-color`）で、タイプが `settings.book` に id で選ぶ。名前は設定の項目ではなく、`book-update` の `title` で変える
- 1 冊だけのタイプ（`single: true`）は、その 1 冊のデータを定義に持つ。何冊も作れるタイプは `create` で空のブックを作る

## アイテム

- kind を持つ（画面に置ける `shape`、2 つの形をつなぐ `connector`）
- 並べ方を知らない。持つのは自分の形・大きさ・つなぎ口と、能力の宣言まで。能力は型の表 `CapabilityTable` に書き足して作る（土台の `connectable`・`resizable` のほかは `<プラグインの id>:<名前>`）。土台が意味を知るのは土台の 2 つだけで、足した能力は足したプラグインの処理が読む。名前の頭は `createMatomezu` の型が確かめる。並べるのはブックのタイプ
- 並べ方から描くもの（ツリーの線など）は、データに無いのでアイテムにしない
- 項目の形（`props`）は Zod。ブックのデータの検査は、そのブックが使うアイテムの項目を集めて組み立てる。AI には、そのブックで使えるアイテムだけを見せる
- 知らないアイテムが来ても壊さない（枠だけ描き、データは消さない）。機能台帳に無いアイテム（プラグインを外したなど）がページにあってもブックは読め、データはそのまま残す。形は枠だけで描き（大きさはデータの `w`・`h`、無ければ 64×64）、選ぶ・動かす・消すはできるが中身は変えられない。線は描かない。決まりの確かめでは、知らない形はつなげる物として扱う。機能台帳にあってタイプが選んでいないアイテムと、項目の形が合わないアイテムは、今どおり読めない（N005）
- 形の追加と編集のダイアログ（`dialogs.add`・`dialogs.edit`）は、どちらも書かなくてよい。無ければ追加はそのまま置き、編集は「設定」を出さない。渡す値は土台が決めた `ShapeAddArgs`（`{ page, at }`）・`ShapeEditArgs`（`{ page, item }`）で、名指したダイアログがその値を受けるかを型で確かめる
- 形の紙に置くための値（`sizeOf`・`captionWidth`・`min`）は、どれも書かなくてよい。無ければ大きさは置いたときの `w`・`h`（無ければ定義の `size`）、キャプションの幅は定義の `size.w`、`min` が無ければ大きさを変えられない
- キャプション（形の名前として見せる文字）を持つ形は、定義の `captionProp` にその項目の名前を書く。土台はその項目が変わったときだけ、見える幅まで形を広げる。`captionProp` の無い形は、`caption` という項目があっても大きさを変えない。名指した項目が `props` に無ければ誤り（型と E028）
- 個別のテーマ（その形だけ別のテーマで描く値）を持つ形は、定義の `themeProp` にその項目の名前を書く。土台は名指した項目だけをテーマの id として確かめ（無いテーマなら置く・変えるを断る）、ほかの形の `theme` という項目は見ない。名指した項目が `props` に無ければ誤り（型と E028）
- つなぐものはツールボックスに出さない（`toolbox` は `false` だけ書ける。型で確かめる）
- 端の形が無くなったつなぐもの（機能台帳にあるもの）は、形が変わったあとに土台が消す。つなぐものの `tidy` に任せない
- 中身の欄（リストの行など）は、形の定義の `content` に好きな名前でいくつでも宣言できる。ビューには欄の名前ごとに渡し（`content: { 欄の名前: [...] }`）、中の物の id もブックの中で重ならないように振る
- つなぐものが形に求める見た目（薄くする形・強調する形）は `ShapeMarksProvider` で渡す。つなぐものが いくつあっても求めを合わせる: 薄くするのは、どれかが薄くすると求めた形。強調するのは、内側のつなぐものから見て最初に求めた形

## 設定の項目

- 値は ページ → ブック → 定義の既定 の順に、最初に値のある所で決まる。既定を持たない項目は、どこにも値が無ければ読む側が決める（テーマはブックのタイプのテーマ、紙の色はテーマの紙の色）
- 設定のダイアログは、タイプが選んだ項目のビュー（`settingViews`）を並べる。変えている項目は、確定の前からブックに重ねて見せる（ダイアログの下書き）
- 機能台帳に無い設定の項目（プラグインを外したなど）は、使わずにデータに残し、設定のダイアログに出さない。機能台帳にあってタイプが選んでいない項目は読めない（N005）
- 名前は id の 1 つだけ（`field` は持たない）。変える鍵もデータに残す鍵も設定の id で、データはブックとページの `settings` という欄の中に入れる（例: `settings: { "@matomezu/line:line-route": "elbow" }`）

## アクション

- 対象（`library`・`book`・`settings`）を宣言する
- `run` は新しい値と結果を返す純粋な関数。対象に合わなければ null を返して断る。引数の形は Zod
- 通すのは `core/perform.ts` の `perform`（使えるか → 引数の形 → run → 関係の決まり）
- `library` と `settings` のアクションを許すかは、ホームのブックのタイプが決める
- ブックを作るアクション `book-create`（と「新しいブック」のダイアログ・コマンド）は base が持つ。どのホームのタイプも `actions.add` で選べる
- 同じ入力なら同じ結果を返す。使うのは文脈（`ActionContext`）の物だけで、時刻や乱数を直に使わない。新しい id は `ctx.newId()` で振る
- 時刻は `ctx.now`（UTC の ISO 8601。最初に行った所が 1 回だけ決め、画面からホストへ `ids` と一緒に送り、行い直しでも同じ値）。アクションの定義が時刻や乱数を直に使っていないことを `test/rules.test.ts` が見張る
- ブックが対象のアクションは、付く先を `attach` に書く: `items`（そのアイテムを置けるタイプ）・`presentations`（その見せ方のタイプ）・`pages: true`（ページを持つタイプ）・`books: true`（どのタイプも）。どれか 1 つに当てはまれば使える。`attach` の無いアクションは、タイプの `add` で選ばれたときだけ使える
- `attach` に `pages` か `items` を書いたアクションの `run` には、ページを持つブックの型（`PagedBook`）で渡す（`books`・`presentations` も書いたら `Book` のまま）。`perform` はページの無いブックには断る。プラグインは言い張り（`as`）を書かない
- アクションを行うコマンドは、行うアクションを `performs` に書く。どれかが今のブック（ブックが対象でなければホームのタイプ）で使えなければ、土台はそのコマンドを出さない（メニュー・右クリックのメニュー・ツールボックス・キーのどれからも）。`when` は、出すコマンドの中で決める
- `without` に付いていないアクション、`add` にすでに付いているアクション、`performs` に表に無いアクションを書いたら、その行だけ効かず、注意（N001〜N003）を残す

## AI に見せる

- AI（MCP）には、アクションを 1 つずつ道具にしない。決まった道具で渡す: 今使えるアクションの一覧（id・引数の JSON Schema・AI 向けの説明）とアイテム・テーマ・代表色・言語・スキンを返す `actions` と、`{ action, args, on }` で行う `perform`。ほかは読む道具（`view`・`list_books`・`read_book`・`read_settings`）と `show`。追加プラグインを足し・外しても、MCP の道具の一覧は変わらない
- アクションは全部 AI に見せる（利用者の設定のアクションも。行えるかは画面と同じく、ホームのブックのタイプが決める）
- MCP で AI に見せるもの（アクション・アイテム・タイプの名前、アクションの説明、断った理由の文）は英語に固定し、利用者の言語に合わせない。名前は英語の文言（`en`）で引く
- AI 向けの説明（英語）は、アクションの定義の `aiDescription` に書く（どう変わるか・何を返すか・断る場合）。追加プラグインも自分のアクションの説明を書く

## テーマ

- 色・線の種類・影・角の丸みなど、並べ方を変えないものだけ。文字の大きさや余白は変えない
- アイテムとブックのタイプは、自分の使う欄と既定（共通の欄 `fallback` か値 `value`）を宣言する。欄の宣言は 1 か所だけ
- テーマは知っている欄だけを上書きする
- 欄ごとに light と dark の値を持てる。両方を書いた欄は、見る人の OS の明暗で切り替える
- プラグインの見た目では、自分が宣言した欄を `--<名前>` の CSS 変数で使う（例: 欄 `@foo/stars:star-fill` → `var(--star-fill)`）。matomezu が、そのプラグインのアイテムとブックの見せ方を描く要素に、そのプラグインの欄だけを短い名前で置く（ほかのプラグインの欄は置かないので、ぶつからない）。欄の名前は `theme-`・`skin-` で始めない（土台の CSS 変数とぶつかるため。組み立てが確かめる）
- 土台の欄（`accent`・`paper`・`text` など）は、どこでも `--theme-<名前>` で使う
- 欄の値を置く中の CSS 変数の名前は、matomezu の中だけのもので、開発者は書かない。ビルトインプラグインの CSS が参照する欄が、宣言した欄にあることをテストが見張る

## id

- 1 つのインスタンスの中で、種類ごとに一意。データに残る id は、ほかのマシンやほかの人の matomezu でも同じものを指す
- プラグインが足す物の id は `<プラグインの id>:<名前>`（例: `@foo/stars:star`・`@matomezu/box:shape-box`）。ビルトインプラグインも同じ。定義の種類・テーマの欄・ウィジェット・スロット・キーの範囲・メニューのどれも
- 名前に使える字は英小文字・数字・`-` だけで、先頭は英小文字（kebab-case）。プラグインの id（npm のパッケージ名）は `:` を含まないので、区切りを見誤らない
- `:` の無い名前は土台の言葉（スロットの `root`、キーの範囲の `stage`・`dialog`・`menu`・`global`、土台の欄の `accent` など）
- キーの範囲・スロット・メニュー・右クリックのメニュー・能力の名前は、型の表（`KeyScopeTable`・`SlotTable`・`MenuTable`・`ContextMenuTable`・`CapabilityTable`）に書き足して作る。土台の言葉のほかは `<プラグインの id>:<名前>` で、渡したプラグインの id で始まるかを `createMatomezu` の型が確かめる
- プラグインは自分の物を短い名前で定義する。プラグイン API の `pluginKit(プラグインの id, 文言)` が返す定義の関数（`kit.defineShape` など）が頭を付け、返した定義の id は長い形（型も）。自分の物は返した定義（`STAR.id`）か `kit.name(名前)` で名指し、ほかのプラグインの物は長い id で書く
- ブックのタイプの `schema` に `type` は書かず、`create` の返すブックにも書かない。1 冊だけのタイプの `book` には `type`・`id` を書かない（`kit.defineBookType` が本当の id で足す）
- 組み立ては、どのプラグインの物も、id がそのプラグインの id と `:` で始まり、名前が決まりの字だけかを確かめる（ビルトインプラグインも例外にしない）
- コマンドのアイコン（`commandIcons`）は、自分のコマンドにだけ付けられる（組み立てが E307 で確かめる）
- ブックの id は uuid（1 冊だけのタイプのブックは、タイプの id）。ページとアイテムの id は `freshId`（ブックの中で重ならない短い id）。ホストとのやり取りの URL に入れるときは、URL エンコードする
- アクションの名前は「対象-動き」（例: `page-add`・`line-connect`）
- 文言の鍵は id ではないので、字の決まりは無い（英語の文を鍵にしてよい）。中の鍵は `<プラグインの id>:<鍵>` で、`pluginKit` に渡した文言に頭を付け、見た目では `useMessages(kit)` が短い鍵で引く。プラグインの文言は英語の文（`en`）を必ず持つ（組み立てが E304 で確かめる）
