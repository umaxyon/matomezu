# 定義と機能台帳

機能は、定義（Def）を機能台帳に足すことで増やす。定義はどれもプラグインが持ち込む。

## 定義の表

| 表 | 何か | 置き場所 |
|---|---|---|
| ブックのタイプ（`BookTypeDef`） | ブックのデータの形・並べ方の決まり・使うアイテムとアクションの選択 | `core/def/book-type.ts` |
| アイテム（`ItemDef`） | 名詞。データに残り、画面に置かれるもの（箱・ひし形・線など） | `core/def/item.ts` |
| アクション（`ActionDef`） | 動詞。データを変える唯一の入口 | `core/def/action.ts` |
| テーマ（`ThemeDef`） | ブックの中身の見た目 | `core/def/theme.ts` |
| スキン（`SkinDef`） | アプリの枠の見た目（利用者の設定で選ぶ） | `core/def/skin.ts` |
| 紙（`PaperDef`） | ページに置く紙の大きさ | `core/def/paper.ts` |
| 文字の色（`TextColorDef`） | 本文の一部に付ける、意味の役割の色（成功・注意など）。色を持つ | `core/def/text-color.ts` |
| 設定の項目（`SettingDef`） | ブックやページ、または利用者の設定に持たせる 1 つの値（線の既定の通り方・言語など） | `core/def/setting.ts` |
| 見せ方（`PresentationDef`） | ブックをステージにどう見せ、どう触るか（紙など） | `core/def/presentation.ts` |
| 道具（`ToolDef`） | ステージでポインタが何をするか（選択・ハンドなど） | `core/def/tool.ts` |
| 道具の組（`ToolSetDef`） | ステージで切り替える道具の並び | `core/def/tool.ts` |
| 認可ステップ（`PermissionDef`） | アクションを、ブックのある所で行うのを止める（ロックなど）。止めるだけで、許すことはしない | `core/def/permission.ts` |
| コマンド（`CommandDef`） | 画面の入口（ボタン・メニュー・キーから呼ぶ） | `store/commands/def.ts` |
| ダイアログ（`DialogDef`） | 開くダイアログの id | `store/dialogs.ts` |
| 文言の組（`MessageSetDef`） | プラグイン 1 つの、画面に出す文と訳（id は `<プラグインの id>:messages`） | `core/i18n/messages.ts` |
| 言語パック（`LanguagePackDef`） | 言語 1 つの名前と、どのプラグインの文言にも足せる訳（id は `<プラグインの id>:<言語>`） | `core/i18n/messages.ts` |
| テーマキー（`TokenDef`） | テーマの値の名前と既定 | `core/def/theme.ts` |
| キーの既定の割り当て（`KeyDef`） | キーとコマンドの組 1 つ | `store/keys.ts` |

- 定義の種類（文言の組・言語パック・テーマキー・キーの既定の割り当てを除く上の表）の一覧は `core/catalog.ts` の `PARTS`（フィールドの名前・入る台帳・error の文の名前）と `PartTables`（id の表）だけに書く。定義の型は、その台帳の層が `PartDefTable` に書き足す（core の種類は `core/core-catalog.ts`、store の種類は `store/plugin.ts`）。プラグインのフィールド（`PluginParts`）・core 台帳と store 台帳・id の頭と重なりの検査は、この一覧から作る。種類ごとに意味の違う見た目のフィールド（`definePluginUi`）と定義を書く関数（`pluginKit` の `define…`）は、`ui/part-ui.ts` の `PART_UI` に種類ごとに書く（種類が抜けると型の誤り。書いたフィールドと関数があることはテストが確かめる）
- 文言の組・言語パック・テーマキー・キーの既定の割り当ては、プラグインの `messages`・`languages`・`tokens`・`keys`（テーマキーはアイテムとブックのタイプの `tokens` にも）に書き、`PARTS` に入れない。どれも id を持ち、機能台帳が id ごとに 1 つ並べる（アイテムとブックのタイプのテーマキーは、機能台帳には並ばず、その定義オブジェクトの中にある）。同じ id は error。定義を書く関数（`kit.defineKey`・`kit.defineLanguagePack`）は `ui/part-ui.ts` の `NON_PART_DEFINES` に書く。文言の組は `pluginKit` が作り、土台の文言の組と言語の id の頭は `matomezu`（`matomezu:messages`・`matomezu:en`・`matomezu:ja`）
- 定義は `defineX()` で書く。React を使わない（描き方はプラグインの見た目で結ぶ）

- core 台帳は定義の組から作り、作ったあとは変えない。作るときに表どうしの参照を確かめ、食い違えば作らない
- core の関数は使う表を最初の引数（`catalog`。core 台帳）で受け取り、アクションは `ctx.catalog` で受け取る

## 拡張ポイント

- どの定義オブジェクトの型も、種類ごとの拡張ポイントを含む。土台のファイルの定義オブジェクトの型に書くのは、土台が読むフィールド・メソッドだけ。ほかのプラグインが読むものは、読む側のプラグインが拡張ポイントに書き足す。いくつものプラグインが使う見込みのものは base が書き足す
- 拡張ポイントは `core/catalog.ts`（追加プラグインからは `matomezu/catalog`）の `BookTypeExtras`・`ShapeItemExtras<D>`・`ConnectorItemExtras<D>`・`ActionExtras`・`ThemeExtras`・`TokenExtras`・`PaperExtras`・`TextColorExtras`・`SkinExtras`・`SettingExtras`・`PresentationExtras`・`ToolExtras`・`ToolSetExtras`・`PermissionExtras`・`MessageSetExtras`・`LanguagePackExtras`・`CommandExtras`・`DialogExtras`・`KeyExtras`・`WidgetExtras`・`LayoutExtras`・`BookViewExtras`。形とつなぐものの拡張ポイントは、置いたデータの型 `D` を受ける（書き足すときも同じ型引数で書く）
- base が書き足す名前は短い名前。base 以外は `"<プラグインの id>:<名前>"`。書き足したプラグインは、自分の名前を `kit.name` で引く
- 追加プラグインが、ほかのプラグインに答えてもらう書き足しは、そのプラグインのコードとは別の連携ポイントに置く。書き足したプラグインも、答えるプラグインも、それを `import type` で読む（型だけなので変換で消える。値で読むと error）
- ビルトインプラグインどうしは、連携ポイントを作らない。同じプログラムの中で、読む側が書き足した型を共に使う
- 組み立ては、知らないフィールド・メソッドを error にしない（定義オブジェクトはそのまま機能台帳に並ぶ）。書き足したフィールドを確かめるのは、書き足したビルトインプラグインの組み立てのときの確かめ（`checks`。error は core の error の表に足す）で、追加プラグインは持てない（型と組み立ての両方で止める）

## 参照の向き

- ブックのタイプは、アイテム・アクション・テーマ・道具の組を id で選ぶ。関係はこの選択（リスト）で表す
- アイテムとアクションは、ブックのタイプを知らない。アイテムはアクションを知らない（アクションは付く先 `attach` に、扱うアイテムの id を書く）
- タイプの名前を見て振る舞いを分ける判定や、データの形を見てタイプを推し量る判定は作らない。使えるかは、タイプが選んだリストで決まる
- タイプが違うブックの互換は土台で定義しない。1 枚のページに並べ方の違うものを混ぜず、並べ方が違えばタイプを分ける

## ブックのタイプ

- 使えるアイテムは、タイプが候補（`allowed`。データに置ける物）と既定（`defaults`。ツールボックスに出す物）を持つ
- 使えるアクションは、タイプが選んだ物について来る（アクションの `attach`）。タイプの `actions` は、そのタイプだけのアクションを足す `add` と、使わせない `without` だけを書く（アクションを並べる `allowed`・`defaults` は持たない）
- 名前（`title`）は土台の言葉で、どのタイプのブックも持つ（空でもよい。空なら画面はタイプの名前で呼ぶ）。ロック（`locked`）とゴミ箱に入れた時刻（`trashed`）も土台のフィールド。フィールドは機能台帳が足し、タイプは schema に名前・ロック・ゴミ箱に入れた時刻・テーマ・紙の色を書かない（書けば error）
- 道具の組は、プラグインが `defineToolSet` で持ち、タイプは `tools` で id で名指す。同じ組を名指すタイプは、同じ道具を共有する。道具の定義（`ToolDef`）のフィールドは、土台が読む `pans`・`places`・`performs` だけ。`performs` はその道具で行うアクションで、開いているページで、どれも認可ステップに止められるなら、その道具は使えず、組の次の使える道具になる。ほかの動きは、ビューが今の道具を見て決めるか、読む側のプラグインが拡張ポイントに書き足す
- データの形の外の決まり（アイテムどうしの関係）は `holds` に書く。アクションの結果が守らなければ断り、守らないブックは読めない（warning にする）
- ブックが対象のアクションの結果は、`perform` が機能台帳のブックの形と `holds` で確かめ直し、合わなければ断る（型を言い張った所があっても、ここで止める）
- ページを持つブックを変える土台の関数は、渡されたブックの型のまま返す（`<B extends PagedBook>`）。ページを替えるのは `putPage` で、ページの中身がタイプの選んだアイテムかを型で示せない所の言い張りはここに閉じる。プラグインはブックを `{ ...book, pages }` で組み直さない
- タイプはページに自分のフィールドを足せる（`pages.fields`。ページがすでに持つフィールドと同じ名前は error）。ページ → ブック → 既定と引き継ぐ値は設定の項目（`settings`）にし、引き継がない、そのタイプのページだけのデータは `pages.fields` にする
- タイプだけの設定の項目（`settings` の book・page）とページのフィールド（`pages.fields`）は base のアクションが受け付け、タイプの宣言した形で確かめる。ブックの設定の項目は `book-create`・`book-update`、ページの設定の項目とページのフィールドは `page-add`・`page-update`。ページのフィールドの受け方（受ける形と、ページへの書き方）は、タイプが決められる。タイプは、ページに問題があることを知らせられる（知らせの文言は任意）。base のアクションは、問題のあるページを書かない。断ったことを利用者に知らせるか、どう知らせるかは、呼んだ側が決める。タイプごとの作る・更新のアクションは作らない
- タイプは、ページを作るダイアログとページの設定のダイアログを id で名指せる（`pages.dialogs`。名指さなければ base のもの）。作るほうは値を受けず、設定のほうは土台が決めた `PageSettingsArgs` を受ける。名指したダイアログがそうなっているかを型で確かめる。行うのは base の `page-add`・`page-update` で、ダイアログのために別のアクションを作らない
- ブックのテーマと紙の色は、base が定義する設定の項目（`@matomezu/base:book-theme`・`@matomezu/base:book-paper-color`）で、タイプが `settings.book` に id で選ぶ。名前は設定の項目ではなく、`book-update` の `title` で変える
- 文字の色の値は、定義の色を、ブックのテーマの `textColors`（base が拡張ポイントに書き足したフィールド。文字の色の id → 色）で変え、base が定義するブックの設定の項目（`@matomezu/base:book-text-colors`。文字の色の id → 色）で上書きする。ブックの設定で上書きできるのは、タイプが `settings.book` に選んだブックだけ
- 1 冊だけのタイプ（`single: true`）は、その 1 冊のデータを定義に持つ。何冊も作れるタイプは `create` で空のブックを作る

## アイテム

- kind を持つ（画面に置ける `shape`、2 つの形をつなぐ `connector`）
- 並べ方を知らない。持つのは自分の形・大きさ・つなぎ口と、能力の宣言まで。能力は `core/catalog.ts` の `CapabilityTable` に書き足して作る（土台の `connectable`・`resizable`・`nests` のほかは `<プラグインの id>:<名前>`）。土台が意味を知るのは土台の 3 つだけで、足した能力は足したプラグインの処理が読む。名前の頭は `createMatomezu` の型が確かめる。並べるのはブックのタイプ
- 能力 `nests` のある形は、子の形の並び `shapes` を持てる。中に置くのは、そのブックのタイプが選んだ形だけ。空の並びは持たない。子の位置は親の左上から測る
- つなぐものはページの `items` にだけ置く。端はどの深さの形でもよい
- 形を id で探すときは、どの深さの子の形も探す
- 形を並べる決まりは、同じ Frame の中の形どうしにかける。子の領域は子に合わせて広がる。子の領域の中では、押した形を縮めない
- 並べ方から描くもの（ツリーの線など）は、データに無いのでアイテムにしない
- 項目の形（`props`）は Zod。ブックのデータの検査は、そのブックが使うアイテムの項目を集めて組み立てる。AI には、そのブックで使えるアイテムだけを見せる
- 知らないアイテムが来ても壊さない（枠だけ描き、データは消さない）。機能台帳に無いアイテム（プラグインを外したなど）がページにあってもブックは読め、データはそのまま残す。形は枠だけで描き、選ぶ・動かす・消すはできるが中身は変えられない。線は描かない。決まりの確かめでは、知らない形はつなげる物として扱う。機能台帳にあってタイプが選んでいないアイテムと、項目の形が合わないアイテムは読めない（warning にする）
- 形の追加と編集のダイアログ（`dialogs.add`・`dialogs.edit`）は、どちらも書かなくてよい。無ければ追加はそのまま置き、編集は「設定」を出さない。渡す値は土台が決めた `ShapeAddArgs`・`ShapeEditArgs` で、名指したダイアログがその値を受けるかを型で確かめる
- 形の紙に置くための値（core のフィールドの `min` と、base が拡張ポイントに書き足した `sizeOf`・`captionWidth`）は、どれも書かなくてよい。無ければ大きさは置いたときの `w`・`h`（無ければ定義の `size`）、キャプションの幅は定義の `size.w`、`min` が無ければ大きさを変えられない
- キャプション（形の名前として見せる文字）を持つ形は、定義の `captionProp`（base が拡張ポイントに書き足したフィールド）にその項目の名前を書く。base はその項目が変わったときだけ、見える幅まで形を広げる。`captionProp` の無い形は、`caption` という項目があっても大きさを変えない。名指した項目が `props` に無ければ error（型と組み立てで確かめる）
- 個別のテーマ（その形だけ別のテーマで描く値）を持つ形は、定義の `themeProp`（base が拡張ポイントに書き足したフィールド）にその項目の名前を書く。base は名指した項目だけをテーマの id として確かめ（無いテーマなら置く・変えるを断る）、ほかの形の `theme` という項目は見ない。名指した項目が `props` に無ければ error（型と組み立てで確かめる）
- つなぐものはツールボックスに出さない（base が拡張ポイントに書き足した `toolbox` は、つなぐものでは `false` だけ書ける。型で確かめる）
- 端の形が無くなったつなぐもの（機能台帳にあるもの）は、形が変わったあとに base が消す。つなぐものの `tidy` に任せない
- 中身のフィールド（リストの行など）は、形の定義の `content` に好きな名前でいくつでも宣言できる。ビューにはフィールドの名前ごとに渡し（`content: { フィールドの名前: [...] }`）、中の物の id もブックの中で重ならないように振る
- つなぐものが形に求める見た目（薄くする形・強調する形）は `ShapeMarksProvider` で渡す。つなぐものがいくつあっても求めを合わせる: 薄くするのは、どれかが薄くすると求めた形。強調するのは、内側のつなぐものから見て最初に求めた形
- ミニマップに描く絵は、定義の `minimap` に書く（書かなくてよい。base のミニマップが拡張ポイントに書き足したメソッド）。返すのは紙の座標の簡単な絵 `MinimapMark`（四角・楕円・多角形・折れ線）で、色と線の太さはミニマップが決める。形は 1 つずつ、置いた四角を渡して聞き、無ければその四角を描く。つなぐものは種類ごとにまとめて、`bounds` と同じ引数で聞き（通り方がほかの線で決まるため）、無ければ描かない

## 設定の項目

- 値は ページ → ブック → 定義の既定 の順に、最初に値のある所で決まる。既定を持たない項目は、どこにも値が無ければ読む側が決める（テーマはブックのタイプのテーマ、紙の色はテーマの紙の色）
- 設定のダイアログは、タイプが選んだ項目のビュー（`settingViews`）を並べる。変えている項目は、確定の前から重ねて見せる（ダイアログの下書き）
- 機能台帳に無い設定の項目（プラグインを外したなど）は、使わずにデータに残し、設定のダイアログに出さない。機能台帳にあってタイプが選んでいない項目は読めない（warning にする）
- 名前は id の 1 つだけ（`field` は持たない）。変える鍵もデータに残す鍵も設定の id で、データはブックとページの `settings` というフィールドの中に入れる（例: `settings: { "@matomezu/line:line-route": "elbow" }`）
- 利用者の設定の項目は、プラグインの `userSettings` に置く。1 つの id を、ブックの設定の項目と利用者の設定の項目の両方には使わない。利用者の設定も、機能台帳に無い項目を使わずに残す
- 土台は、自分が読む利用者の設定の項目（言語・スキン・キーの割り当て）を、id でなく `role` で引く。`role` を持てるのはビルトインプラグインの項目だけで、1 つの `role` は 1 つの項目だけが持つ。言語パック・スキン・キーを足すプラグインは `role` を書かない（足した物は、その項目の選択肢になる）
- 利用者の設定の項目ごとに、変えるアクションを作らない（変えるのは base のアクション 1 つ）

## アクション

- 対象（`library`・`book`・`settings`）を宣言する
- `run` は新しい値と結果を返す純粋な関数。対象に合わなければ null を返して断る。引数の形は Zod
- 通すのは `perform`（使えるか（認可ステップを含む）→ 引数の形 → run → 認可ステップが行った後に確かめる → 関係の決まり）
- `library` と `settings` のアクションを許すかは、ホームのブックのタイプが決める。ホームのタイプは、利用者の設定の項目のうち変えさせない物を id で選べる（`fixedUserSettings`。利用者にも AI にも）
- ブックを作るアクション `book-create`（と「新しいブック」のダイアログ・コマンド）は base が持つ。どのホームのタイプも `actions.add` で選べる
- 同じ入力なら同じ結果を返す。使うのは文脈（`ActionContext`）の物だけで、時刻や乱数を直に使わない。新しい id は `ctx.newId()` で振る
- 時刻は `ctx.now`（UTC の時点を ISO 8601 の文字で。最初に行った所が 1 回だけ決め、行い直しでも同じ値）。アクションの定義が時刻や乱数を直に使っていないことを `test/rules.test.ts` が見張る
- ブックが対象のアクションは、付く先を `attach` に書く: `items`（そのアイテムを置けるタイプ）・`presentations`（その見せ方のタイプ）・`pages: true`（ページを持つタイプ）・`books: true`（どのタイプも）。どれか 1 つに当てはまれば使える。`attach` の無いアクションは、タイプの `add` で選ばれたときだけ使える
- `attach` に `pages` か `items` を書いたアクションの `run` には、ページを持つブックの型（`PagedBook`）で渡す（`books`・`presentations` も書いたら `Book` のまま）。`perform` はページの無いブックには断る。プラグインは言い張り（`as`）を書かない
- ブックが対象のアクションは、ブックのどこを変えるかを許可の範囲（`permissionScope`）に書く（無ければ型の誤り）。`"book"`（ページもアイテムも変えない）か、所を表す自分の引数の名前（`{ page, item, items }`）。名前で言えなければ、引数から所を返す関数。利用者の設定が対象のアクションも、変える項目を許可の範囲に書く（項目の id を鍵に持つ自分の引数の名前か、引数から項目の id を返す関数）
- アクションを行うコマンドは、行うアクションを `performs` に書く。どれかが今のブック（ブックが対象でなければホームのタイプ）で使えなければ、土台はそのコマンドを出さない（メニュー・右クリックのメニュー・ツールボックス・キーのどれからも）。どれも認可ステップに止められるなら、土台はそのコマンドを出したまま押せなくする。`when` は、出すコマンドの中で決める。キーは、今使えるコマンドの割り当てのうち、狭い範囲から先に見つかった物が効く（使えない割り当ては無いものとして、次の範囲の同じキーを探す。使える物が無ければ何もしない）
- ブックが対象のアクションを行うコマンドは、許可の範囲（`permissionScope`）を書く（無ければ型の誤り）。`"book"`・`"opened-page"`（開いているページ）・`"selection"`（選んでいるアイテム）か、呼ばれた場所の様子から所を返す関数
- ブックが対象のアクションのうち、図の内容でなくブックの扱いを変える物（ロックの掛け外しなど）には `history: false` を書く。書いたアクションは画面の履歴に入らない
- プラグインは、戻す・やり直すための逆のアクションを作らない。戻すのは base が画面の履歴の段から行う
- `without` に付いていないアクション、`add` にすでに付いているアクション、コマンドと道具の `performs` に表に無いアクション、タイプの `fixedUserSettings` に利用者の設定の項目でない id を書いたら、その行だけ効かず、warning を残す

## 認可ステップ

- 認可ステップ（`PermissionDef`）は、アクションを使えるかを決めるステップの中で、ブックのタイプのステップの前に並ぶ。止めるだけで、許すことはしない（使えるかはブックのタイプが決める。認可ステップを足しても、できることは広がらない）
- 行う前は、アクションの許可の範囲から出した所で聞かれ、止めるかを答える。この答えは見せ方に使う。データを守るのは、行った後に、前と後のブックの変化で確かめる方（行う前に所が分からない・粗いときも、ここで止まる）
- 同じ入力なら同じ答えを返す（アクションと同じ。時刻・乱数・外の状態を見ない）
- 止めたら `perform` は、止めた認可ステップの id を添えて断る。画面の各機能は、その id を見て、薄くする・消す・色を変えるなどを自分で決める
- ロックは base の認可ステップ（`@matomezu/base:lock`）。アクションの `run` はロックを確かめない。ロックを外すアクションは利用者だけ（`userOnly`）

## AI に見せる

- AI（MCP）には、アクションを 1 つずつ MCP 公開ツールにしない。決まった MCP 公開ツールで渡す: 今使えるアクションの一覧（id・引数の JSON Schema・AI 向けの説明）とアイテム・テーマ・代表色・文字の色・言語・スキンを返す `actions`（今の warning も。architecture の「warning」）と、アクションを行う `perform`。ほかは読む MCP 公開ツール（`view`・`list_books`・`read_book`・`read_settings`）と `show`。追加プラグインを足し・外しても、MCP 公開ツールの一覧は変わらない
- アクションは全部 AI に見せる（利用者の設定のアクションも。行えるかは画面と同じく、ホームのブックのタイプが決める）。ただし、利用者だけが行うアクション（`userOnly`）は見せず、AI が頼んでも断る。利用者の設定の項目の `userOnly` も同じく、AI に見せず（AI が読む設定にも出さない）、AI が変えようとしても断る
- MCP で AI に見せるもの（アクション・アイテム・タイプの名前、アクションの説明、断った理由の文）は英語に固定し、利用者の言語に合わせない。名前は英語の文言（`en`）で引く
- AI 向けの説明（英語）は、アクションの定義の `aiDescription` に書く（どう変わるか・何を返すか・断る場合）。追加プラグインも自分のアクションの説明を書く
- 認可ステップが止めたときは、止めた認可ステップの id と、その定義の `aiDescription`（英語。何がなぜ止めたか）を AI に返す
- 文字の色の意味（英語）は、文字の色の定義の `aiDescription` に書く。本文の装飾の書き方は、本文の項目の形の説明（`describe`）で AI に見せる

## テーマ

- 色・線の種類・影・角の丸みなど、並べ方を変えないものだけ。文字の大きさや余白は変えない
- アイテムとブックのタイプは、自分の使うテーマキーと既定（共通のテーマキー `fallback` か値 `value`）を宣言する。テーマキーの宣言は 1 か所だけ
- いくつものアイテムが共に使うテーマキー（8 つの形の塗りなど）は、アイテムでなくプラグインが持つ（`kit.plugin({ tokens })`。id は `kit.name` で長い形に書く）
- ブックを描くのに使うテーマキーは、タイプのテーマキーと、タイプが置けるアイテム（`items.allowed`）のテーマキーと、そのアイテムの持ち主のプラグインが持つテーマキー
- テーマは知っているテーマキーだけを上書きする（文字の色はテーマキーではなく、base の `textColors` で変える）
- テーマキーごとに light と dark の値を持てる。両方を書いたテーマキーは、見る人の OS の明暗で切り替える
- プラグインの見た目では、自分が宣言したテーマキーを `--<名前>` の CSS 変数で使う（例: テーマキー `@foo/stars:star-fill` → `var(--star-fill)`）。matomezu が、そのプラグインのアイテムとブックの見せ方を描く要素に、そのプラグインのテーマキーだけを短い名前で置く（ほかのプラグインのテーマキーは置かないので、ぶつからない）。テーマキーの名前は `theme-`・`skin-` で始めない（土台の CSS 変数とぶつかるため。組み立てが確かめる）
- 土台のテーマキー（`accent`・`paper`・`text` など）は、どこでも `--theme-<名前>` で使う
- テーマキーの値を置く中の CSS 変数の名前は、matomezu の中だけのもので、開発者は書かない。ビルトインプラグインの CSS が参照するテーマキーが、宣言したテーマキーにあることをテストが見張る

## id

- 1 つのインスタンスの中で、種類ごとに一意。データに残る id は、ほかのマシンやほかの人の matomezu でも同じものを指す
- プラグインが足す物の id は `<プラグインの id>:<名前>`（例: `@foo/stars:star`・`@matomezu/box:shape-box`）。ビルトインプラグインも同じ。定義の種類・テーマキー・ウィジェット・スロット・キーの範囲・メニュー・右クリックのメニュー・能力・その場の編集の名前のどれも
- 名前に使える字は英小文字・数字・`-` だけで、先頭は英小文字（kebab-case）。プラグインの id（npm のパッケージ名）は `:` を含まないので、区切りを見誤らない
- `:` の無い名前は土台の言葉（スロットの `root`、キーの範囲の `stage`・`dialog`・`menu`・`global`、土台のテーマキーの `accent` など）。土台の文言の組と言語パックの id だけは `matomezu:<名前>`（`matomezu:messages`・`matomezu:en`）
- キーの範囲・スロット・メニュー・右クリックのメニュー・能力の名前は、`core/catalog.ts`（`KeyScopeTable`・`SlotTable`・`MenuTable`・`ContextMenuTable`・`CapabilityTable`）に書き足して作る。土台の言葉のほかは `<プラグインの id>:<名前>` で、渡したプラグインの id で始まるかを `createMatomezu` の型が確かめる
- プラグインは自分の物を短い名前で定義する。プラグイン API の `pluginKit(プラグインの id, 文言)` が返す定義の関数（`kit.defineShape` など）が頭を付け、返した定義の id は長い形（型も）。自分の物は返した定義（`STAR.id`）か `kit.name(名前)` で名指し、ほかのプラグインの物は長い id で書く
- その場の編集の名前（`setEditing` に渡す名前）は、表に書き足さず `kit.name(名前)` で作る。ただの文字を渡さない
- ブックのタイプの `schema` に `type` は書かず、`create` の返すブックにも書かない。1 冊だけのタイプの `book` には `type`・`id` を書かない（`kit.defineBookType` が本当の id で足す）
- 組み立ては、どのプラグインの物も、id がそのプラグインの id と `:` で始まり、名前が決まりの字だけかを確かめる（ビルトインプラグインも例外にしない）
- コマンドのアイコン（`commandIcons`）は、自分のコマンドにだけ付けられる（ほかのプラグインのコマンドに付けたら、組み立てが error にする）
- ブックの id は uuid（1 冊だけのタイプのブックは、タイプの id）。ページの id は `freshId`（ほかのページと重ならない短い id）。ページの中で作る物（アイテム・その中身・ページのフィールドの中の物）の id は、ブックの全部のページの中で重ならないように振る。ホストとのやり取りの URL に入れるときは、URL エンコードする
- アクションの名前は「対象-動き」（例: `page-add`・`line-connect`）
- 文言の鍵は id ではないので、字の決まりは無い（英語の文を鍵にしてよい）。中の鍵は `<プラグインの id>:<鍵>` で、`pluginKit` に渡した文言に頭を付け、見た目では `useMessages(kit)` が短い鍵で引く。プラグインの文言は英語の文（`en`）を必ず持つ（無ければ組み立てが error にする）
