# コードの書き方

## コメント

- コメントには、コードが表す実体についての普遍的な説明だけを書く
- その時の状況でしか意味を持たない言い方は書かない（時が過ぎると意味が無くなるか、誤りになるため）
  - 書かない例: 「新しい」「前の作りでは」（前があった含み）、「仮の」「今は」「とりあえず」（ある時期だけの話）、作業の経緯や決めた日付、開発しているマシンの事情
  - 経緯や決めた理由はコミットのメッセージと `docs/` に書く
- `test/rules.test.ts` が一部の言葉を見張る

## データとビュー

- データ（ステージ・workspace・ブックなど）は、ただのデータの型と純粋な関数の組で書く（クラスにしない）。そのデータの決まり（範囲に収める・置き場所を決めるなど）もデータの側に書く
- 土台のデータは `web/src/core/`、プラグインのデータはそのプラグインの中の、見た目でないファイルに置く
- ビューは React のコンポーネントで、データ X を描くコンポーネントの名前は `XView`。データと同じ名前のコンポーネントは作らない
- ビューは計算しない。データを読んで描き、起きたこと（測った大きさ・動いた量など）をそのまま store の操作に渡す。指を離せば消える一時の状態（ドラッグの途中の位置など）だけはビューに持ってよい
- ビューは、ドラッグ・つまみ・入力Form などで変更を始める前に、そのアクションを行えるか（`useAllowed`。コマンドを呼ぶなら、そのコマンドを押せるか）を聞き、行えなければ始めない
- コンポーネントは store を直に触らず、コマンドは `useCommand(stage, id)` で呼ぶ。アクションは、ステージが開いているブックには `usePerform(stage)`、ほかの対象（一覧・設定）には `useActions()` の `perform` で行う

## 文言

- 画面などに出す文言は `t()` を通す。ui とプラグインの `.tsx` に日本語を直に書かない
- 文言は表に書く（土台は `web/src/core/i18n/messages.ts`、プラグインはそのプラグインの `messages.ts`）
- 鍵に字の決まりは無い（英語の文を鍵にしてよい）。`pluginKit` が鍵に `<プラグインの id>:` を付ける（definitions の「id」）
- 文言は英語の文（`en`）を必ず持ち、訳の無い言語では `en` を出す。ビルトインプラグインは日本語の訳も持つ
- `{name}` は `t()` に渡す値で置き換える。プラグインの見た目では `useMessages(kit)`、土台の文言は `useT()`、core の操作では言語を受け取って `translate(lang, ...)`
- 画面の文言は文章にせず、何が起きたかと原因を短い行に分ける

## 使う技術

- 画面は React、状態は Zustand、データの形は Zod（v4）
- 見た目は CSS 変数と CSS Modules（Tailwind は使わない）。ブックの中身の色は、土台のテーマキーが `--theme-*`、プラグインが宣言したテーマキーが `--<名前>`（definitions の「テーマ」）、文字の色が `--text-color-*`（ステージがブックの要素に置く。テーマキーではない）。アプリの枠の色は `--skin-*`
- 文字の幅と折り返しは、フォントのデータから base（`plugins/base/text`）で計算する（画面でも常駐でも同じ行になる）。太字の字は太字の幅で測る
- 本文の装飾は、本文の文字列の中に書く（Markdown の一部）。`**太字**` と `{名前:文字}`（文字の色。base の色は名前だけ、ほかのプラグインの色は id で書く）。対にならない記号は文字のまま。色が機能台帳に無ければ、記号は外して色を付けない。HTML としては描かない
- 整形と lint は Biome（セミコロンを省く）
- 保存されるデータのフィールドの並びは変えない（保存されたデータと Go のテストに出る）
