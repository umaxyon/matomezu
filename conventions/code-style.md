# コードの書き方

## コメント

- コメントには、コードが表す実体についての普遍的な説明だけを書く
- その時の状況でしか意味を持たない言い方は書かない。テストの題名も同じ（時が過ぎると意味が無くなるか、誤りになるため）
  - 書かない例: 「新しい」「前の作りでは」「今まで通り」（前があった含み）、「仮の」「今は」「とりあえず」（ある時期だけの話）、作業の経緯や決めた日付、開発しているマシンの事情
  - 経緯や決めた理由はコミットのメッセージと `docs/` に書く
- テストが一部の言葉を見張る

## データとビュー

- データ（ステージ・ブックスクリーン・ブックなど）は、ただのデータの型と純粋な関数の組で書く（クラスにしない）。そのデータの決まり（範囲に収める・置き場所を決めるなど）もデータの側に書く
- 土台のデータは `web/src/core/`、プラグインのデータはそのプラグインの中の、見た目でないファイルに置く
- ビューは React のコンポーネントで、データ X を描くコンポーネントの名前は `XView`（「X ビュー」と片仮名で読んでよい。`BoxView` はボックスビュー。アイテムそのものは用語集の名前で呼ぶ）。データと同じ名前のコンポーネントは作らない
- ビューは計算しない。データを読んで描き、起きたこと（測った大きさ・動いた量など）を、そのまま store を操作するフック（`useCommand`・`usePerform` など）に渡す。指を離せば消える一時の状態（ドラッグの途中の位置など）と、そのビューが出している間だけの確かめや入力の途中の値（ビューが消えれば消え、ほかのビューもコマンドも読まない物。確かめのモーダルを出しているかなど）だけはビューに持ってよい
- 1 回の操作で行うアクションは、同じ同期の処理の中で続けて行う（画面の履歴の段とアクションバルクは、同期の処理ごとに切れる。await・setTimeout の後は別になる）。利用者の操作の描き直しで走る `useEffect` のアクションも、同じアクションバルクに入ることがある（決まりは「定義と機能台帳」の「アクション」）。ドラッグ・つまみの途中の値はビューに持ち、離したときに行う。あとの同期の処理で行うアクションを、そのステージエントリの直前の画面の履歴の段に足すなら、行う前に `continueStep` を呼ぶ
- ビューは、ドラッグ・つまみ・入力Form などで変更を始める前に、そのアクションを行えるか（`useAllowed`。コマンドを呼ぶなら、そのコマンドを押せるか）を聞き、行えなければ始めない
  - ステージが開いていないブックに問うときと、書庫が対象のアクション（変えるブックが引数で決まる）は `useAllowedOn`
- コンポーネントは store を直に触らず、コマンドは `useCommand(id)` で呼ぶ。アクションは、ステージの中で、そのステージが開いているブックとそのページには `usePerform()`（ページが対象のアクションなら、宛先のページを渡す）、ほかの対象（一覧・設定）には `useActions()` の `perform` で行う（アクションと続けて行う操作を組み合わせる関数は、アクションを持つプラグインが出す。「構造とクレート」の「状態を変える所」）

## 文言

- 画面などに出す文言は `t()` を通す。ui とプラグインの `.tsx` に日本語を直に書かない
- 文言は表に書く（土台は `web/src/core/i18n/messages.ts`、プラグインはそのプラグインの `messages.ts`）
- 鍵に字の決まりは無い（英語の文を鍵にしてよい）。`pluginKit` が鍵に `<プラグインの id>:` を付ける
- 文言は英語の文（`en`）を必ず持ち（無ければ台帳アセンブルが error にする）、訳の無い言語では `en` を出す。ビルトインプラグインは日本語の訳も持つ
- `{name}` は `t()` に渡す値で置き換える。言語で語順の違う文の中に部品（選ぶボタンなど）を置くときは、値を渡さない印 `{name}` を文言に書き、base の `TextAround` でその所に部品を置く（前と後ろを別の文言に分けない）。プラグインの見た目では `useMessages(kit)`、土台の文言は `useT()`、core の操作（アクションの `run` など）では `ctx.catalog.messages` と `ctx.lang` で `translate(messages, lang, key)`（プラグイン API が出す）
- 画面の文言は文章にせず、何が起きたかと原因を短い行に分ける

## 使う技術

- 画面は React、状態は Zustand、データの形は Zod（v4）
- 見た目は CSS 変数と CSS Modules（Tailwind は使わない）。ページの見た目の CSS 変数は「定義と機能台帳」の「テーマ」。スキンの色は `--skin-<スキンキー>`、外観枠の代表色は `--skin-palette-<役割>`（その上の字は `-ink`）、matomezu 外観枠で描くコードの色は `--skin-code-<種類>`
- 文字の幅と折り返しは、フォントのデータから base（`plugins/base/text`）で計算する（画面でも常駐でも同じ行になる）。太字の字は太字の幅で測る
- 本文の装飾は、本文の文字列の中に書く（Markdown の一部）。`**太字**` と `{名前:文字}`（文字の色。base の色は名前だけ、ほかのプラグインの色は id で書く）。対にならない記号は文字のまま。記号の字（`*`・`{`・`}`・`\`）の前の `\` は、その字を文字にする。色が機能台帳に無ければ、記号は外して色を付けない。HTML としては描かない
- 整形と lint は Biome（セミコロンを省く）
- 保存されるデータのフィールドの並びは変えない（保存されたデータと Go のテストに出る）
